## 코드 리뷰의 4단계 기준

| 순서 | 기준 | 질문 |
|------|------|------|
| 1 | **동작** | 요구사항대로 동작하는가? |
| 2 | **안전성** | 메모리 누수, 경계 초과, NULL 참조는 없는가? |
| 3 | **가독성** | 6개월 후에도 이해할 수 있는가? |
| 4 | **확장성** | 기능 추가 시 얼마나 많은 곳을 수정해야 하는가? |

> 리뷰는 **비난이 아니라 위험 제거 활동**이다.
> "이 코드가 틀렸다"가 아니라 "이 부분에서 NULL일 수 있지 않을까?"

## 리팩터링 기법

### 1. 매직 넘버 제거

```c
/* Before */
char buf[256];
if (count > 100) { ... }

/* After */
#define BUF_SIZE 256
#define MAX_ENTRIES 100
char buf[BUF_SIZE];
if (count > MAX_ENTRIES) { ... }
```

### 2. 중복 코드 함수화

```c
/* Before */
for (int i = 0; i < n; i++) sum1 += arr1[i];
for (int i = 0; i < m; i++) sum2 += arr2[i];

/* After */
int sum_array(const int *arr, int n) { ... }
sum1 = sum_array(arr1, n);
sum2 = sum_array(arr2, m);
```

### 3. 긴 함수 분해

```c
/* Before: 100줄짜리 main */
int main(void) {
    /* 초기화 30줄 */
    /* 처리 50줄 */
    /* 정리 20줄 */
}

/* After */
static int init(void) { /* 30줄 */ }
static void process(void) { /* 50줄 */ }
static void cleanup(void) { /* 20줄 */ }

int main(void) {
    if (init() != 0) return 1;
    process();
    cleanup();
    return 0;
}
```
