| R5 | **업적 3개 이상** 을 이벤트로 처리 (예: 10연속 격추, 무피격 웨이브 클리어, 보스 첫 처치) | 업적 Model 이 게임 Model 이벤트(`drainEvents`)를 **구독**해 판정. 게임 Model 은 업적을 모름. 달성 알림은 View |
| R6 | **하이스코어 저장 / 불러오기** | Model 은 문자열 직렬화 / 역직렬화만 (`io`, `love` 금지). 파일 입출력은 `main.lua` 에서만. 깨진 파일이면 기본값으로 시작하고 죽지 않음 |
| R7 | **번짐 실측**: 마지막에 "새 적 종류 1종 추가"를 하고 변경이 어느 계층에 몰렸는지 측정 | 아래 3절 방법으로 측정한 표 + 해석을 보고서에 기록 |

공통 규칙
- `layer_check` 를 **통과**해야 합니다. 규칙: Model 은 `love` · `io` · `print` 금지, View / Controller / Scene 은 `love` 금지, `love` 를 아는 파일은 `main.lua` 하나.
- 전역 변수 금지(`local` 만), Lua 5.1 / LuaJIT 호환 (`//`, `goto`, `utf8`, 정수 나눗셈 등 5.3+ 문법 금지).
  - 전역 쓰기 확인 (LuaJIT, 아무것도 출력되지 않아야 함):
    `for f in $(find project/src -name "*.lua"); do luajit -bl "$f" | grep -q GSET && echo "전역 쓰기: $f"; done`
  - week07 `tests/globals_check.lua` 를 참고해 자기 프로젝트용으로 고쳐 써도 됩니다.
- **새 테스트 케이스 10개 이상** 추가: 파서(정상 · 경계 · 오류) 3개 이상, 적 AI 전이 3개 이상, 저장 / 불러오기 2개 이상, 새 씬 1개 이상. week05 `tests/helper.lua` 를 그대로 써도 됩니다.
  - week05 `equivalence_test.lua` 는 week04 코드를 비교 대상으로 읽으므로 그대로 복사하면 실패합니다. 쓰지 않을 거면 제출물에서 빼세요.

가산 메뉴 (선택, 과목별 가산 기준은 각 공지 참조)

## 3. 번짐 실측(R7) 방법

1. R1 ~ R6 이 끝나면 커밋하고 태그를 붙입니다: `git tag before-r7`
2. 새 적 종류 1종을 추가하고 (테스트 포함) **커밋**합니다. 새 파일은 커밋해야 집계됩니다.
3. 계층별 변경 덩어리(hunk) 수를 셉니다. Git Bash / 터미널에서:

```bash
for d in models views controllers scenes; do
  printf "%-12s %s\n" "$d" "$(git diff -U0 before-r7 HEAD -- project/src/$d | grep -c '^@@')"
done
git diff --stat before-r7 HEAD -- project/
```

4. 보고서에 표로 옮기고 **"왜 이 계층만 바뀌었나 / 바뀌지 말았어야 할 곳이 바뀌었나"** 를 3~5줄로 해석합니다.
   - 참고: 4주차 실측 (2주차 모놀리식 41 hunk vs 4주차 MVC 25 hunk)

## 4. AI 협업 기록 (worklogs) — 두 과목 공통, 각 과목 10점

기본 양식은 [학생 가이드 9절](../../docs/ai/prompt-engineering-guide-student.md) 과 키트의 `worklog-writer` 스킬 양식을 따릅니다.

### 4-1. 최소 요건 (미달 시 해당 과목 로그 점수 상한 5점)
- 세션 로그 **5개 이상**, **서로 다른 날짜 3일 이상** (`worklogs/NNN_YYYY-MM-DD_session.md`)
- 세션마다: 목표 한 문장, 시작 / 끝 커밋 해시, 검증 결과(테스트 명령과 결과)
- 프롬프트 기록 **10개 이상** (원문 그대로), 그중 **거절 또는 수정 사례 3개 이상**
- 최종 회고 `worklogs/999_retrospective.md`

### 4-2. 꼭 들어가야 하는 기록 3가지
1. **"AI 가 틀렸고 내가 잡았다" 2건** — Lua 함정 1건(게임시스템설계용), 구조 · 패턴 문제 1건(게임인공지능용)
2. **경계 위반 거절 1건 이상** — `layer_check` 출력 **원문** + 거절 이유 + 고친 프롬프트 (2건 중 구조 쪽과 겹쳐도 됨)
3. **명세 기반 프롬프트 1건** — README · 계약 문서 · 테스트를 첨부해 구현시킨 기록. "첨부 없이 vs 첨부하고" 비교가 있으면 개선 이력으로 인정

"AI 가 틀렸고 내가 잡았다" 양식:

```markdown
## AI 오류 포착 #1 (게임시스템설계 / 게임인공지능)
- 관련 프롬프트: 프롬프트 기록 #N (커밋 abc1234)
- 증상: (무엇이 이상했나, 에러 원문)
- 원인 위치: project/src/models/WaveParser.lua:23
- 발견 방법: 테스트 실패 / layer_check / 실행 / 코드 읽기
- 고친 방법과 다음 프롬프트에 추가한 제약:
```

### 4-3. 최종 회고 (`999_retrospective.md`) 양식

```markdown
# 최종 회고

## AI 에 맡긴 것 / 직접 한 것
| 작업 | AI | 나 | 비고 (대략 비율, 근거 로그 번호) |
|---|---|---|---|

## 가장 효과가 컸던 프롬프트 기법 1개와 근거 로그
## 가장 크게 실패한 프롬프트 1개와 그 후 바꾼 점
## 직접 만든 스킬 / 규칙 (권장): 파일 경로, 적용 전후 차이
## 다음에 다르게 쓸 프롬프트 3가지
```

### 4-4. 로그를 어떻게 검증하나 (시연 대신)
- 로그의 커밋 해시를 `docs/git_log.txt` 와 대조합니다. 없는 해시, 시간 순서가 맞지 않는 기록은 감점합니다.
- 마감 직전 하루에 세션이 몰려 있으면 "날짜 3일" 요건을 충족하지 못한 것으로 봅니다.
- 채점자가 로그의 프롬프트 1~2개를 골라 **같은 조건으로 다시 실행**해 볼 수 있습니다. 첨부 파일과 도구를 기록해 두세요.
- 개인정보, 비밀번호, API 키는 로그에 넣지 않습니다.

## 5. 제출 구조 (두 과목 동일한 압축파일)

```text
학번_이름_기말/
  README.md              ← 실행 방법, 테스트 명령, 출발 코드(A/B), 조작법
  run.sh / run.bat       ← 가능한 경우
  project/
    src/                 ← main.lua, conf.lua, models/, views/, controllers/, scenes/, waves.txt
    tests/               ← helper.lua, layer_check.lua, *_test.lua
  docs/
    waves_format.md
    git_log.txt          ← git log --stat --date=iso > docs/git_log.txt
    report_게임시스템설계.md
    report_게임인공지능.md
  worklogs/
    001_YYYY-MM-DD_session.md ...
    999_retrospective.md
```

- 테스트는 `project/tests` 에서 `luajit layer_check.lua src` 처럼 앱 폴더 이름 `src` 로 실행되게 합니다 (week05 helper 그대로 동작).
- README 의 명령만으로 **테스트 실행 → 게임 실행** 이 재현되어야 합니다. `luajit` 대신 `lua5.1` 을 쓴다면 README 에 적습니다.
- 필수 구조 누락은 즉시 0점 처리하지 않고, 안내 후 재제출 1회를 허용합니다.

## 7. 자주 묻는 질문

Q1. 두 과목에 다른 프로젝트를 내야 하나요?
- 아니요. **같은 압축파일**을 두 게시판에 올리고, 과목별 보고서만 따로 업로드합니다.

Q2. AI 가 코드를 거의 다 짰으면 감점인가요?
- 비율 자체로 감점하지 않습니다. 대신 **설명 문항**(각 과목 공지)에 자기 코드 줄 번호로 답하지 못하거나, 로그와 커밋이 맞지 않으면 감점됩니다.

Q3. 공개된 week05 ~ 07 완성본을 그대로 써도 되나요?
- 출발 코드로는 됩니다(선택 B). 필수 요건 R1 ~ R7 은 공개 완성본에 없는 기능이므로 그 부분이 채점 대상입니다.

Q4. 실행은 되는데 일부 버그가 있으면요?
- 0점은 아닙니다. 버그의 증상, 원인 추정, 개선 계획을 보고서 "알려진 문제" 에 적으면 부분 점수를 받습니다.
