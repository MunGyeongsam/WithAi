# `string.find`, `string.match`, `string.gmatch` 연습 힌트

> 앞서 제시한 100개 문제의 힌트입니다. 힌트는 접근 방향만 제공하며 완성 코드는 포함하지 않습니다.
> Lua 패턴은 정규식과 다르므로 `%d`, `%a`, `%s`, `^`, `$`, `()`의 의미를 먼저 확인하세요.

## Lv.1 기초 찾기 (1-20)

1. `string.find(text, "apple", 1, true)`의 결과가 `nil`인지 확인한다.
2. `string.find(text, "game", 1, true)`의 첫 번째 반환값을 사용한다.
3. 일반 문자열 검색을 사용하고, 대소문자 변환은 요구하지 않는다.
4. 공백을 리터럴로 검색한다.
5. 콤마는 패턴에서 특별한 문자가 아니므로 그대로 검색한다.
6. `string.find`에 세 번째 인자로 시작 위치를 주어 마지막 결과를 갱신한다.
7. 문자열 시작을 나타내는 `^`와 리터럴 `ID:`를 조합한다.
8. 문자열 끝을 나타내는 `$`를 `.png` 패턴과 조합한다. 점은 `%.`로 쓴다.
9. 포함 여부만 필요하므로 `string.find`의 결과가 있는지만 본다.
10. `://`는 plain 모드 검색으로 확인하면 안전하다.
11. 첫 번째 매치 뒤의 위치에 1을 더해 다음 검색 시작 위치로 사용한다.
12. 이전 매치의 끝 다음부터 검색하는 과정을 세 번 반복한다.
13. 세 번째 인자에 `6`을 넣어 검색 범위를 제한한다.
14. `find` 루프에서 매치 끝 다음 위치부터 다시 검색한다.
15. `[`와 `]`는 패턴 문법이므로 리터럴 검색 또는 `%[`와 `%]`를 사용한다.
16. 숫자 한 개 이상은 `%d+`로 찾는다.
17. 숫자가 아닌 문자 한 개 이상은 `%D+`로 찾는다.
18. 대문자는 `%u`로 찾는다.
19. 검색 시작 위치를 5로 지정하고 `%l`을 사용한다.
20. 점을 그대로 찾을 때는 plain 모드 또는 `%.`를 사용한다.

## Lv.2 find 패턴 확장 (21-35)

21. 단어 앞뒤가 영숫자가 아닌지 확인하려면 앞뒤 경계 조건을 별도로 생각한다. `find`만으로는 경계 처리가 제한적이다.
22. 공백 하나가 아니라 `%s%s+`처럼 연속 공백을 표현한다.
23. 각 숫자 덩어리를 `%d+`로 표현하고 점은 `%.`로 이스케이프한다.
24. 숫자 네 자리, 하이픈, 숫자 두 자리, 하이픈, 숫자 두 자리를 순서대로 조합한다.
25. 여는 큰따옴표와 닫는 큰따옴표 사이를 `.-`로 최소 매칭한다.
26. `<(.-)>` 형태의 최소 매칭을 위치 검색용으로 바꿔 생각한다.
27. 함수명 패턴 뒤에 여는 괄호가 오는지 확인한다. 괄호는 리터럴로 이스케이프한다.
28. `0x` 뒤에 `%x+`가 오는 패턴을 만든다.
29. Lua 주석의 시작 표시는 `--`이며, plain 모드 검색이 간단하다.
30. 괄호는 `%(`, `%)`로 리터럴 처리한다.
31. 사용자명과 도메인을 각각 `%w` 또는 허용할 문자 집합으로 표현한다.
32. 소수점은 `%.`, 정수 부분과 소수 부분은 `%d+`로 표현한다.
33. 탭과 공백은 `%s`로 찾는다.
34. 숫자 한 덩어리는 `%d+`이며 반환된 시작/끝 위치로 구간을 자른다.
35. 경로 토큰은 `/`가 포함된 연속 문자열로 잡되, 입력 조건에 맞춰 허용 문자를 좁힌다.

## Lv.3 match 기초 추출 (36-50)

36. 첫 숫자 덩어리를 `%d+`로 `string.match`한다.
37. `@` 앞의 문자를 캡처하고, 사용자명 허용 문자를 정한다.
38. `@` 뒤부터 도메인 끝까지를 캡처한다.
39. 마지막 확장자만 원하면 `%.([%w]+)$`처럼 문자열 끝을 고정한다.
40. `^(%a+)://`에서 첫 번째 캡처를 반환한다.
41. 숫자 그룹 세 개를 괄호로 캡처하고 하이픈은 리터럴로 둔다.
42. `(%d+):(%d+)`처럼 콜론 양쪽을 각각 캡처한다.
43. `(%w+)=(%S+)` 형태로 key와 value를 두 번 반환받는다.
44. 문자열 시작에서 공백이 아닌 덩어리를 찾는다.
45. 마지막 단어는 문자열 끝 앵커 `$`를 활용한다.
46. 괄호와 콤마를 리터럴로 처리하고 숫자 캡처를 세 개 둔다.
47. `x=(%d+),y=(%d+)`처럼 고정된 키 뒤의 값을 캡처한다.
48. 부호는 `%-?`, 숫자는 `%d+`로 표현한다.
49. 정수부와 소수부를 각각 캡처하고 점은 `%.`로 쓴다.
50. `(.)%1`처럼 캡처된 문자와 같은 문자를 다시 요구하는 패턴을 검토한다.

## Lv.4 match 중급 파싱 (51-65)

51. 시작은 `[%a_]`, 나머지는 `[%w_]`로 만들고 `^...$`로 전체 검증한다.
52. 선택적인 공백은 `%s*`, 변수명과 숫자값은 캡처 그룹으로 분리한다.
53. `local` 뒤 공백과 변수명, `=` 뒤 숫자를 순서대로 캡처한다.
54. 함수명은 첫 캡처, 괄호 안 전체는 두 번째 캡처로 잡는다. 괄호 내용은 최소 매칭을 고려한다.
55. 콜론을 리터럴로 두고 key와 따옴표 안 value를 각각 캡처한다.
56. 대괄호는 `%[`와 `%]`로 처리하고 레벨과 메시지를 나눈다.
57. 대괄호 안 날짜/시간 캡처를 먼저 만들고 닫는 대괄호 뒤 메시지를 캡처한다.
58. 점은 `%.`로 이스케이프하고 숫자 그룹 세 개를 캡처한다.
59. `#` 뒤의 16진수 두 자리씩을 세 그룹으로 캡처한다.
60. 마지막 점 뒤 확장자를 제외하려면 끝 앵커와 탐욕적 패턴의 차이를 확인한다.
61. `^(#+)%s+(.+)$`로 샵 묶음과 제목을 분리한다.
62. key와 value 양쪽에 `%s*`를 배치하고 value 끝의 공백을 제외한다.
63. `T`와 `:`를 고정 문자열로 두고 날짜와 시간을 각각 캡처한다.
64. `function` 뒤 식별자 패턴을 캡처하고 여는 괄호 전에서 멈춘다.
65. 마지막 점 뒤 세그먼트는 `([%w_]+)$` 형태로 찾는다.

## Lv.5 gmatch 기초 순회 (66-80)

66. `for word in string.gmatch(text, "%a+") do` 형태로 순회한다.
67. 단어를 출력하는 대신 카운터를 1씩 증가시킨다.
68. 숫자 덩어리 패턴 `%d+`를 iterator에 넣는다.
69. 마지막 셀까지 처리하려면 CSV 뒤에 구분자를 하나 덧붙이는 방법을 검토한다.
70. 해시 기호 뒤 식별자를 `#([%w_]+)`로 캡처한다.
71. `@`와 사용자명 전체를 매치하거나 사용자명만 캡처한다.
72. 슬래시가 아닌 문자를 `[^/]+`로 순회한다.
73. 줄바꿈이 아닌 문자 하나 이상을 `[^
]+`로 순회한다.
74. `([^&=]+)=([^&]*)`처럼 앰퍼샌드와 등호를 구분자로 사용한다.
75. 숫자 양쪽이 더 많은 숫자의 일부가 되지 않도록 경계 조건을 함께 검토한다.
76. 키와 숫자를 캡처하는 패턴을 반복한다.
77. 캡처한 단어를 `string.lower`로 정규화한 뒤 빈도 테이블의 키로 사용한다.
78. 여는 태그와 닫는 태그를 구별해야 하므로 `<%/?([%w]+)`의 의미를 확인한다.
79. 큰따옴표 안의 내용을 `"(.-)"`로 최소 매칭한다.
80. 날짜 패턴을 `gmatch`에 넣어 발견 순서대로 처리한다.

## Lv.6 gmatch 고급 파싱 (81-90)

81. 식별자 시작 문자와 나머지 문자를 나누어 토큰 패턴을 설계한다.
82. 함수명 뒤에 `(`가 오는 토큰을 찾고, 괄호 자체는 결과에서 제외할지 결정한다.
83. `%d+`로 추출한 문자열을 `tonumber`로 변환해 배열에 넣는다.
84. 부호 선택 패턴 `%-?`와 소수 선택 부분을 조합한다.
85. 줄 단위 순회 후 `^%s*TODO:%s*(.-)%s*$`로 항목만 추출한다.
86. key는 식별자, value는 따옴표 안 최소 매칭으로 캡처한다.
87. 각 줄에서 `^%[(%u+)%]`를 match하고 레벨별 카운터를 증가시킨다.
88. 중첩 괄호까지 처리하려면 일반 패턴보다 `%b()` 균형 매치를 검토한다.
89. 모듈명과 함수명을 식별자 세그먼트로 나누되 점을 리터럴로 둔다.
90. `(%w+)%s+%1` 형태의 캡처 재참조를 이용해 중복 단어를 찾는다.

## Lv.7 종합/어려움 (91-100)

91. `find`가 찾은 뒤 시작 위치에 1만 더해 겹치는 `ana`를 놓치지 않게 한다.
92. 줄 단위로 순회한 뒤 제목 패턴의 `#`와 텍스트를 캡처하고 줄 위치를 별도로 센다.
93. 줄의 첫 문자가 `[`이면 섹션, 그렇지 않으면 첫 `=` 위치를 기준으로 key/value를 나눈다.
94. 공백 기준 순회만으로는 따옴표 안 공백을 보존할 수 없으므로 `gmatch` 패턴을 따옴표 토큰과 일반 토큰으로 설계한다.
95. `{{(.-)}}`로 플레이스홀더 이름을 캡처하고 `find` 반환 위치를 함께 기록한다.
96. Apache 로그의 공백 필드와 따옴표 필드를 구분하는 토큰 패턴을 만든다.
97. `-`도 유효한 필드 값으로 취급하고, 따옴표 필드는 최소 매칭으로 읽는다.
98. 링크 텍스트와 URL을 각각 캡처한 뒤 `gmatch`로 여러 링크를 순회한다.
99. 줄 단위 순회, 레벨 캡처, 타임스탬프/모듈/메시지 캡처, 카운트 집계를 단계별로 나눈다.
100. 현재 위치에서 `find`로 다음 토큰을 찾고, `match`로 토큰 값을 추출하며, 반복 가능한 부분은 `gmatch`로 처리한다. 문자열 리터럴과 주석을 먼저 인식해야 내부 기호를 잘못 해석하지 않는다.

## 힌트 사용 순서

1. 먼저 입력 예시와 원하는 출력 형태를 직접 작성한다.
2. 힌트의 패턴을 작은 문자열에 적용해 `print`로 매치 결과를 확인한다.
3. 캡처가 여러 개이면 반환값을 각각 변수에 받고 `nil` 가능성을 검사한다.
4. 반복 문제는 결과를 바로 출력하지 말고 테이블에 수집해 검증한다.
5. 패턴만으로 처리하기 어려운 문제는 `find`, `sub`, `tonumber`, `table.concat`을 함께 사용한다.
