## 2. 시간이 밀릴 때 줄이는 순서
1. 3-4 T4 → 숙제 (단, 되돌리기 안내는 꼭).
2. 2-4 F3 실기 → 시연만.
3. 9절 퀴즈 → 숙제.

## 3. 시연: 예측 vs 실측 (10분)
- 칠판에 "이 겔러그는 60fps 프레임 예산(16.7ms)의 몇 %를 쓸까?" 를 적고 손을 들게 한다(1%, 10%, 50%…).
- `luajit bench.lua starter` → 0.04~0.06%. **"측정하기 전엔 아무도 몰랐다."**
- 이어서 "그럼 최적화할 게 없나?" → 할당 1244 B/스텝 → 미사일을 끄면 94 B → 원인이 하나로 좁혀진다.
- `luajit -jp=f bench.lua` 를 보여 주면 `measure` 가 70%로 나온다. "도구가 보여 주는 1위가 정답은 아니다."

## 4. 운영 팁
- **bench 숫자가 학생마다 다르다**: 정상이다. 시간은 기계·전원 모드·다른 프로그램에 따라 다르다. **같은 기계에서 전후 비교**만 의미 있다. 할당(JIT 끔)은 거의 같게 나온다.
- **Windows 학생**: `luajit` 가 PATH 에 없으면 `bench`·`run_all`·`globals_check` 정적 겹이 안 된다. `lua5.1` 이 있으면 `lua5.1 run_all.lua starter` 로 돌린다(정적 전역 검사만 생략). 둘 다 없으면 LÖVE 로 실행 확인만 하고 테스트는 짝과 함께.
- **`equivalence_test` 는 6주차 폴더를 상대 경로로 읽는다.** week07 만 따로 복사한 학생은 "module not found" — week06 도 함께 둔다.
- **저장 파일 위치**: LÖVE 저장 폴더(`love.filesystem.getSaveDirectory()`), `conf.lua` 의 `t.identity = "galaga_mvc_week07"`. 완성본과 스타터가 **같은 폴더**를 쓰므로 4-3 실험(버전 불일치)이 된다. 학생이 "파일이 어디 있어요?" 하면 macOS `~/Library/Application Support/LOVE/galaga_mvc_week07`, Windows `%APPDATA%\LOVE\galaga_mvc_week07`.

## 5. 프롬프트 P (T4) — 작성자가 직접 해 본 결과
템플릿 복사본에 P(적 총알 1.5배 + 피격 후 0.5초 무적)를 손으로 구현해 `run_all` 을 돌렸다.

| 경우 | 실패한 묶음 |
|------|------------|
| 버전을 안 올림 | **`equivalence_test` 8개 전부** (+ 원래 실패하던 perf·combo) |
| 버전을 2로 올림 | equivalence 통과(36번째 스텝, 0.6초에 달라짐을 확인) |

- **기존 기능 테스트(`feature_test`·`scene_test` 등)는 하나도 깨지지 않았다.** 총알 속도·무적을 기대값으로 가진 테스트가 없기 때문이다. 즉 "규칙이 바뀌었다"를 알려 주는 것은 `equivalence_test` 하나뿐이다 → 버전 약속 테스트의 가치를 보여 주는 좋은 순간.
- 반대로 말하면, 무적 판정이 틀려도(예: 0.5초가 아니라 영원히) 테스트는 모른다. **새 규칙에는 새 테스트가 필요하다** — 콤보에 `combo_test` 를 먼저 준 이유.

## 6. 예상 질문
| 질문 | 답의 방향 |
|------|----------|
| "0.06%면 최적화 왜 해요?" | 맞다, 시간 때문이면 안 한다. 할당(GC)이 이유이고, 그것도 "지금 PC 에선 체감 없음"이라고 README 에 그대로 썼다. 오늘 배우는 건 최적화 기법이 아니라 **측정 → 근거 → 증명**의 순서. |
| "`homing.nearest` 는 이제 안 쓰는데 지워야 하나요?" | `feature_test` 가 단독 테스트로 쓰고, 다른 투사체가 쓸 수 있는 순수 함수라 두었다. 지울지 말지도 ADR 거리. |
| "버전 대신 옛 규칙을 남기면 되잖아요?" | ADR-000 선택지 C. 가능하지만 Model 을 버전마다 보관해야 한다. 공유 리플레이(랭킹)가 생기면 다시 볼 조건에 적혀 있다. |
| "AI 가 테스트를 고쳐서 통과시키면요?" | 실제로 흔하다. 프롬프트에 "테스트 파일은 고치지 마"를 넣고, diff 에 `tests/` 가 있으면 되돌린다. 테스트가 명세인 이유. |
| "F3 draw 가 0.1ms 인데 FPS 는 60에서 안 올라가요" | vsync. 그리고 draw ms 는 명령을 쌓는 시간이지 GPU 시간이 아니다(2-4). |
| "ECS 는 언제 배워요?" | 계획서 A안에서 제외. 5주차 "못 지운 3줄"(엔티티 종류 축)이 ECS 가 푸는 문제라는 연결만 짚어 준다. |

## 7. 퀴즈 정답 & 채점 포인트 (README 9절)

**1.** Model 이 View 를 모르고(의존성 방향은 고전 MVC 와 같음), View 가 매 프레임 Model 을 읽어(Pull) 그리는 MVC. Passive View 는 Presenter 가 View 를 직접 갱신하고 View 는 Model 을 모른다 — 우리 View 는 Model 을 **읽는다**.

**2.** 불가능하거나 매우 어렵다. 가변 dt 면 같은 입력이라도 프레임 시간에 따라 위치·충돌이 달라져 재생 결과가 기록 당시와 다르다. 고정 스텝은 "스텝 번호 = 시간"으로 만들어 입력을 스텝에 붙일 수 있게 한다.

**3.** 고정 스텝이 여러 번 돌아도 이벤트를 한 번에 소비(연출이 한 프레임에 모임)하고, 소비자가 비워야 큐가 무한히 자라지 않는다. View 가 Model 의 스텝 횟수를 몰라도 된다.

**4.** 스택이 맨 위 씬에만 update 를 주므로, Pause 를 push 하면 Play 는 자동으로 멈추고 상태도 그대로 남는다. 따로 저장·복원할 것이 없다.

**5.** 같은 것: 결정적(같은 입력 → 같은 결과), 상태 변경 경로가 하나(`update`/`reduce`), love 를 모름. 다른 것: GameModel 은 **제자리 수정**이라 옛 상태가 남지 않는다(시간 여행은 처음부터 재실행), 리듀서는 새 state 를 만든다.

**6.** ① 시간은 기계·실행마다 흔들리지만 할당(JIT 끔)은 같은 코드면 같다 → 회귀 테스트로 쓸 수 있다. ② 이 게임은 시간으로는 병목이 없고, 할당이 GC 멈춤의 원인이 된다.

**7.** 증명: 고른 시드·자동 조종·보스전·승리·게임오버 경로에서 6주차와 매 스텝 같다. 못 하는 것: 그 경로 밖(예: 거리가 정확히 같은 동률, 사람의 다른 플레이)까지 같다는 것. `<`→`<=` 변이가 못 잡힌 사례.

**8.** 쓸데없이 올렸다 → 멀쩡한 저장 리플레이가 거부된다. 또는 바꾼다고 생각한 규칙이 실제로는 적용되지 않았다(버그).

**9.** 정적: `_G[name]` 같은 동적 접근. 실행: 실행되지 않은 분기. (lua5.1 에선 정적 겹 자체가 없다.)

**10.** 채점: 비어 있거나 "없음"이면 0점. 구체적일수록(파일·수치) 가점.

## 8. 자주 막히는 곳
- **`_nearestTarget` 에서 보스를 빠뜨림** → `equivalence_test` 가 543번째 스텝(seed 1)에서 실패. "보스전에서만 달라진다"는 힌트를 준다.
- **`e.alive` 검사 누락** → 107번째 스텝. 죽은 적을 향해 미사일이 꺾인다.
- **콤보 `tick` 을 `update` 끝에서 호출** → `combo_test` 는 **통과한다**(확인함). 리플레이 결정성에는 문제없지만 격추 스텝에 이미 1/60초가 빠져 명세("마지막 격추 후 1초")와 한 스텝 어긋난다. "테스트가 통과하면 명세대로인가?" 토론거리.
- **HUD 에서 `game.combo` 가 nil** → 콤보 없는 Model 과 함께 View 를 테스트하면 에러. 템플릿 View 는 Model 과 같이 바뀐다는 것을 짚는다.
- **`globals_check` 정적 겹 "출력이 없다"** → `luajit -bl` 이 `jit.bc` 모듈을 못 찾는 설치. LuaJIT 를 공식 배포본으로 다시 설치하거나 lua5.1 로 실행 겹만.

## 9. 실행 확인 기록 (작성자 검증)
- 헤드리스: `run_all` — 완성본 10/10 묶음 통과, 스타터 8/10(perf·combo 실패가 의도), **luajit·lua5.1 모두 같은 결과**.
- 실제 LÖVE 11.5(macOS) 1회: 임시 복사본 + **임시 저장 identity**(끝나고 폴더 삭제), F3 켬 → 한 판 → 결과 S(SAVED, 216바이트) → 타이틀 L → 끝까지 재생 → 실시간과 플레이어 x·점수 일치, version 2, 오류 없음. 스크립트가 게임오버를 빨리 만들려고 상태를 직접 바꿨다(연결 확인 목적).
- 변이 검사(임시 복사본, 모두 잡힘): 안 도는 분기의 전역 쓰기 / 오타 전역 읽기 / 실행 중 `_G[...]` 쓰기 / 씬의 love(→ globals·layer 둘 다) / 피격 시 콤보 미초기화 / combo 이벤트 순서 / 배율 상한 누락 / 버전 미갱신(equivalence 8 + combo 1) / 최적화 되돌림(perf) / 리플레이 버전 검사 제거 / 기록 헤더 누락.
- 최적화 변이(템플릿 v1 에서): 보스 누락·alive 누락은 잡힘, `<`→`<=` 는 못 잡음(관찰 불가 차이, README 2-5).

## 10. 알려진 한계 (고치지 않음)
- 버전을 2로 올린 뒤의 최적화는 동작 불변을 증명할 그물이 없다. 다음 기준선을 만들려면 `galaga_final` 을 새 "기준 폴더"로 고정하고 `equivalence_test` 의 비교 대상을 옮기면 된다(질문이 나오면 과제로).
- `perf_test` 는 비율(미사일 켬/끔 < 2)만 본다. 미사일과 무관한 할당 증가는 못 잡는다.
- `bench` 는 렌더링(GPU)을 재지 않는다. F3 은 명령 생성 시간만 보여 준다.
- Windows 실기기 검증은 아직 못 했다(경로 구분자·`dir /b` 처리는 4주차부터 같은 방식).
