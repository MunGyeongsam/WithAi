## 5. 개념 퀴즈 정답 & 채점 포인트 (README 6절 ③)

**1. 같은 것 두 가지 / 다른 것 한 가지**
- 같은 것: ① 역할 분담(M 상태·규칙 / V 표시 / C 입력) ② Model 이 View 를 모른다(의존성 방향)
- 다른 것: 갱신 계기 — 고전은 Model 의 변경 통지(Push), 우리는 매 프레임 `love.draw` 가 읽음(Pull)
- ❌ 감점: "고전 MVC 는 Model 이 View 를 안다"

**2. Passive View 가 아닌 이유**
- Passive View 는 View 가 Model 을 **모르고** Presenter 가 값을 넣어 준다. 우리 View 는 Model 을 직접 읽는다.

**3. update 안에서 drain/비우기 하면?**
- 고정 타임스텝에서 한 프레임에 update 가 여러 번 돌면 **앞 스텝 이벤트가 View 에 닿기 전에 사라진다** → 적은 죽었는데 폭발 연출·사운드 누락. 프레임률이 낮을수록(스텝이 많을수록) 자주 발생 → 저사양에서만 나는 버그.
- 가점: "그래서 테스트 `한 프레임 2스텝 후에도 보존` 이 있다"

**4. print 도 금지인 이유**
- Model 이 콘솔(출력 장치)에 묶인다. LÖVE 창·테스트·서버 어디서 돌아도 같아야 한다. 테스트 출력도 오염된다. (basics 7절 첫 번째 실수)

**5. basics 03 Observer 는 디커플링을 깨는가?**
- **깨지 않는다.** Model 은 구독자 **함수 목록**만 갖고 View 를 `require` 하지 않는다. 깨지는 경우는 Model 이 **구체적인 View 를 직접** 참조·호출할 때.
- ❌ 감점: "Observer 는 Model 이 View 를 알게 되므로 깨진다" — 이전 판 오류와 같은 오개념.
