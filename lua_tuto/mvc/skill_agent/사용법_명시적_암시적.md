# 규칙 · 스킬 · 워크플로 · 에이전트 — 동작 방식과 사용법 (명시적 / 암시적)

> 기준: 제공 키트 [kit/.agents/](./kit/.agents) (저장소 루트 `.agents/` 와 같은 내용)
> 도구: **Google Antigravity** (코딩 에이전트), **Gemini 앱** (채팅 + 스킬)
> 개념과 직접 만드는 법: [작성_가이드.md](./작성_가이드.md) · 키트 목록과 설치: [README.md](./README.md)

이 문서의 질문은 하나다. **"내가 부르지 않아도 알아서 쓰이나(암시적), 내가 직접 불러야 하나(명시적)?"**

---

## 0. 한눈에 보기

| 종류 | AI 에게 언제 보이나 | 암시적 트리거 | 명시적 사용 | Gemini 앱 |
|---|---|---|---|---|
| **규칙** | 조건이 맞으면 처음부터 대화 맥락에 들어감 | `always_on`, `glob`, `model_decision` | `@규칙이름` | ❌ (스킬로 대신) |
| **스킬** | 평소엔 이름·설명만 보이고, 필요하다고 판단하면 본문을 읽음 | `description` 과 작업 내용이 맞을 때 | 프롬프트에 스킬 이름을 적음 | ✅ 업로드 후 활성화 |
| **워크플로** | `/이름` 으로 부를 때 절차 전체가 프롬프트로 들어감 | **없음** (간접 연결만 가능) | `/이름` | ❌ |
| **에이전트** | 별도 맥락에서 새로 시작. **지금까지의 대화를 모름** | 메인 에이전트가 `description` 을 보고 위임 (`subagent: true`) | 패널에서 선택 (`mainAgent: true`), 또는 이름을 적어 위임 | ❌ |

**기억할 것 두 가지**
1. 암시적 트리거는 **AI 의 판단이라 확률적**이다. 걸릴 수도, 안 걸릴 수도 있다.
2. **반드시 실행돼야 하는 일**(테스트, 리뷰, 로그 작성)은 명시적으로 부른다.

| 스킬 | `lua-expert` | "문법, 테이블, 메타테이블, 모듈, 성능, 오류 처리를 다룰 때" |
| 스킬 | `love2d-architect` | "아키텍처 설계, 리팩터링, 모듈 분리, 의존성 관리" |
| 스킬 | `love2d-feature-scaffold` | "신규 상태 또는 게임플레이 기능 모듈을 스캐폴딩할 때" |
| 에이전트 | `planner` | 읽기 전용 · "새 기능, 리팩터링, 버그 수정을 시작할 때 먼저" |
| 에이전트 | `lua-reviewer` | 읽기 전용 · "커밋 전 검토, AI 가 만든 코드 점검, 리뷰 요청 시" |
| 에이전트 | `test-runner` | 읽기 + 명령 실행 · "테스트 돌려줘", 커밋 직전 검증 · **서브에이전트 전용** (`mainAgent: false`) |
| 에이전트 | `lua-expert`, `love2d-architect`, `love2d-feature-scaffold` | **수정 가능** (도구 제한 없음) |

> **이름이 겹친다.** `lua-expert` 는 규칙·스킬·에이전트에 모두 있고, `love2d-architect` 와 `love2d-feature-scaffold` 는 스킬·에이전트에 둘 다 있다. 명시적으로 부를 때는 "lua-expert **스킬**로", "lua-expert **에이전트**에게"처럼 **종류를 붙인다.**

## 2. 규칙 (Rules)

### 동작 방식
- `.agents/rules/*.md` 머리말의 `trigger` 가 적용 시점을 정한다. 루트 `AGENTS.md` 는 항상 적용된다.
- 적용된 규칙은 **대화 내내 맥락을 차지**한다. 그래서 짧게 쓴다.

| `trigger` | 언제 | 키트에 있나 |
|---|---|---|
| `always_on` | 항상 | `project-core` |
| `model_decision` | AI 가 `description` 을 보고 판단 | `lua-love2d`, `lua-expert` |
| `glob` | 패턴에 맞는 파일을 다룰 때 | 없음 (직접 만들기: [작성_가이드.md](./작성_가이드.md) 예시 2) |
| `manual` | `@이름` 으로 부를 때만 | 없음 (직접 만들기: [작성_가이드.md](./작성_가이드.md) 예시 3) |

### 암시적 사용 예 3개

| # | 프롬프트 | 걸리는 규칙 | 결과 |
|---|---|---|---|
| 1 | `플레이어 이동 속도 업그레이드 추가해줘` | `project-core` (always_on) | 말하지 않아도 `local M = {} ... return M` 패턴, update/draw 분리, 변경 파일·리스크·검증 방법부터 보고 |
| 2 | `총알 모듈 새로 만들어줘` | `lua-love2d` (model_decision) | "Lua 코드를 수정할 때" 와 맞아서 LuaJIT 호환, 암묵적 전역 금지가 적용 |
| 3 | `EnemyModel 의 nil 에러 고쳐줘` | `lua-expert` (model_decision) | 경계값(nil, 빈 테이블) 처리와 작은 함수 분리가 적용 |

### 명시적 사용 예 3개
1. `@lua-love2d 규칙 기준으로 views/GameView.lua 점검해줘`
   - 판단형 규칙이 안 걸릴까 걱정될 때 직접 지정한다.
2. `@lua-expert 규칙을 우선해서, 성능보다 가독성 위주로 리팩터링해줘`
   - 규칙끼리 부딪힐 때 우선순위를 정한다.
3. `@project-core 의 출력 규칙대로 바뀐 파일과 리스크부터 보여줘`
   - 대화가 길어져 AI 가 형식을 잊었을 때 다시 상기시킨다.

## 3. 스킬 (Skills)

### 동작 방식
- 처음엔 **이름과 `description` 만** 보인다. 작업 내용이 설명과 맞으면 그때 `SKILL.md` 본문을 읽는다.
- 그래서 스킬을 많이 설치해도 맥락 비용이 적다. 대신 **`description` 이 정확해야** 제때 불린다.

### 암시적 사용 예 3개

| # | 프롬프트 | 걸리는 스킬 | 왜 |
|---|---|---|---|
| 1 | `EnemyModel.lua 에 HP 감소 함수 추가해줘` | `lua51-guard` | ".lua 파일을 고칠 때" |
| 2 | `폭발 이펙트 타이머는 어느 폴더에 둬야 해?` | `mvc-boundary` | "새 코드를 어느 계층에 둘지 정할 때" |
| 3 | `오늘 작업 세션 마무리하자` | `worklog-writer` | "세션 마무리" |

### 명시적 사용 예 3개
1. `headless-test-writer 스킬로 웨이브 파서 테스트부터 만들어줘`
2. `game-ai-pattern-coach 스킬로 적 AI 에 State 와 Strategy 중 뭐가 맞는지 힌트만 줘`
3. `prompt-improver 스킬로 이 프롬프트 진단해줘: "적 AI 만들어줘"`

## 4. 워크플로 (Workflows)

### 동작 방식
- `/이름` 을 입력하면 파일의 절차 전체가 프롬프트로 들어가고, AI 가 **그 순서대로** 실행한다.
- 워크플로 안에서 스킬과 에이전트를 이름으로 부를 수 있다. 예: `/end-session` 은 `test-runner` → `lua-reviewer` → `worklog-writer` 를 차례로 쓴다.
- **AI 가 워크플로를 스스로 실행하지는 않는다.** 암시적으로 쓰이게 하려면 아래 "간접 연결" 방법을 쓴다.

### 명시적 사용 예 3개
1. `/start-session`
   - 인계 메모 → 목표 1개 → 수정 허용 파일 → 되돌리기 커밋 → `planner` 계획 → 승인 대기
2. `/end-session`
   - `test-runner` → diff 요약 → `lua-reviewer` → `worklog-writer` → 커밋 메시지 제안
3. `/prompt-expert 적 AI 만들어줘`
   - 뒤에 붙인 문장이 워크플로의 입력이 된다.

### 간접 연결 예 3개 (워크플로에는 진짜 암시적 트리거가 없다)

아래는 **직접 추가해야 하는** 방법이다. 키트에는 들어 있지 않다.

| # | 방법 | 예 | 한계 |
|---|---|---|---|
| 1 | 워크플로 안에서 다른 워크플로 호출 | 직접 만든 `/add-enemy-type` 마지막 단계에 "`/end-session` 을 호출한다" | 첫 워크플로는 내가 불러야 한다 |
| 2 | `always_on` 규칙에 연결 문장 | 규칙에 "커밋하자는 요청을 받으면 `/end-session` 절차를 따른다" | AI 가 절차를 흉내 낼 뿐, 정확한 실행은 보장 안 됨 |
| 3 | 같은 절차를 스킬로도 만든다 | "세션 시작" 절차를 스킬로도 두고 `description` 에 "세션 시작, 오늘 작업 시작" | 스킬이라 확률적. 순서를 꼭 지켜야 하면 워크플로를 직접 부른다 |

> 정리: **"이 순서대로 꼭"** 이면 워크플로를 직접 부르고, **"알아서 적당히"** 면 스킬로 만든다.

## 5. 에이전트 (Agents)

### 동작 방식
- `mainAgent: true` → `/agents` 패널에서 **메인 에이전트로 선택**할 수 있다.
- `subagent: true` → 메인 에이전트가 `description` 을 보고 **일을 맡길(위임)** 수 있다.
- 위임받은 에이전트는 **지금까지의 대화를 모른다.** 맡길 때 파일과 목표를 함께 넘겨야 한다.
- `tools` 로 권한을 제한한다. `planner`, `lua-reviewer` 는 읽기만 할 수 있어 **파일을 못 고친다.**

### 암시적 사용 예 3개

| # | 프롬프트 | 위임되는 에이전트 | 왜 |
|---|---|---|---|
| 1 | `테스트 돌려줘` | `test-runner` | `description` 에 "테스트 돌려줘" |
| 2 | `커밋 전에 방금 만든 코드 검토해줘` | `lua-reviewer` | "커밋 전 검토, AI 가 만든 코드 점검" |
| 3 | `보스 등장 기능 새로 시작하자` | `planner` | "새 기능을 시작할 때 먼저" |

### 명시적 사용 예 3개
1. **패널에서 선택**: `/agents` 에서 `planner` 를 메인 에이전트로 고른다. 그 세션은 **수정할 수 없는 계획 모드**가 된다.
   - `test-runner` 는 `mainAgent: false` 라 패널에 없다. 위임으로만 쓴다.
2. **이름을 적어 위임**: `lua-reviewer 에이전트에게 models/ 폴더 리뷰를 맡기고 결과만 요약해줘`
3. **수정 가능한 에이전트에게 범위를 정해 위임**: `love2d-feature-scaffold 에이전트로 적 스폰 기능 만들어줘. 수정 허용: models/Spawner.lua, tests/spawner_test.lua. 그 외 수정 금지`

> 수정 가능한 에이전트(`lua-expert`, `love2d-architect`, `love2d-feature-scaffold`)에게 맡길 때는 **수정 허용 파일**을 꼭 적는다.

## 6. Antigravity 와 Gemini 앱의 차이

| 항목 | Antigravity | Gemini 앱 |
|---|---|---|
| 규칙 | `AGENTS.md`, `.agents/rules/`, 트리거 4종 | **없음.** "항상 지켜야 할 것"을 스킬로 만들거나 프롬프트에 직접 적는다 |
| 스킬 | `.agents/skills/` 에 두면 자동으로 찾는다 | Customize → Skills 에서 **업로드 + 활성화**해야 쓰인다. 자동으로 쓰이거나 직접 지정할 수 있다 |
| 스킬 암시적 트리거 | `description` 기준 | 같다 (같은 `SKILL.md` 표준) |
| 워크플로 | `/이름` | **없음.** 절차를 프롬프트로 붙여 넣는다 |
| 에이전트 | 위임, 도구 제한, 패널 선택 | **없음.** "너는 읽기 전용 리뷰어다"처럼 역할을 프롬프트로 준다. 권한 제한은 안 된다 |
| 파일 수정 · 명령 실행 | 가능 (명령은 승인 필요) | 불가. 받은 코드를 직접 붙여 넣는다 |
| 업로드 파일 | `antigravity_kit.zip` 을 프로젝트 루트에 풀기 | `gemini_skills/<스킬>.zip` 을 하나씩 업로드 |

Gemini 앱에서 같은 효과를 내는 방법:
- **규칙 대신**: `lua51-guard`, `mvc-boundary` 스킬을 켜 둔다. 그래도 빠지면 프롬프트 첫 줄에 "Lua 5.1, 모든 변수 local, models/ 에서 love.* 금지" 를 적는다.
- **워크플로 대신**: [start-session.md](./kit/.agents/workflows/start-session.md) 의 단계를 복사해 프롬프트로 보낸다.
- **에이전트 대신**: [lua-reviewer.md](./kit/.agents/agents/lua-reviewer.md) 의 System Prompt 부분을 복사해 "이 역할로 아래 코드를 리뷰해" 와 함께 보낸다.

## 7. 암시적 트리거가 안 걸릴 때

| 증상 | 원인 | 해결 |
|---|---|---|
| 스킬이 안 쓰인 것 같다 | 프롬프트가 `description` 과 다르게 표현됨 | 스킬 이름을 적어 명시적으로 부른다. 자주 그러면 `description` 에 내가 쓰는 표현을 추가한다 |
| 규칙을 어긴 코드가 나왔다 | `model_decision` 이 안 걸렸거나 대화가 길어짐 | `@규칙이름` 으로 다시 지정하거나 새 세션을 연다 |
| 엉뚱한 에이전트에게 위임됐다 | `description` 이 겹침 | 에이전트 이름을 적어 위임한다 |
| 워크플로가 실행되지 않았다 | 워크플로는 원래 자동 실행이 없다 | `/이름` 으로 부른다 |
| 같은 이름의 규칙·스킬·에이전트가 헷갈린다 | `lua-expert` 등 이름 중복 | "스킬로", "에이전트에게", "@규칙" 처럼 종류를 붙인다 |

**작업 로그 팁:** 같은 프롬프트를 스킬 이름 **없이 / 넣고** 두 번 보내 결과를 비교하면, 로그의 "개선 이력(Before → After)" 사례가 된다.
