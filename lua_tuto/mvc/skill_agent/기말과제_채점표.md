> 학생 공지: [공통 명세](../../exams/공지_기말과제_공통명세_바이브코딩.md) · [게임시스템설계](../../exams/공지_게임시스템설계(2A)_기말과제_바이브코딩.md) · [게임인공지능](../../exams/공지_게임인공지능(3A)_기말과제_바이브코딩.md)

압축파일 하나로 두 과목을 함께 채점한다. 1단계 공통 확인 결과를 두 과목이 같이 쓴다.

---

## 1단계. 공통 확인 (학생당 약 10분)

```bash
cd 학번_이름_기말
cat README.md                                   # 출발 코드 A/B, 실행 명령 확인
cd project/tests
luajit layer_check.lua src                      # ① 계층 규칙
for t in *_test.lua; do echo "== $t"; luajit "$t" src | tail -1; done   # ② 테스트
cd ../..
for f in $(find project/src -name "*.lua"); do luajit -bl "$f" | grep -q GSET && echo "전역 쓰기: $f"; done  # ③ 전역
ls worklogs | wc -l; ls worklogs                # ④ 세션 수·날짜
```

| # | 확인 | 결과 | 메모 |
|---|---|---|---|
| ① | `layer_check` OK | ☐ | |
| ② | 테스트 전부 통과, 새 케이스 10개 이상 (파서 3 · AI 전이 3 · 저장 2 · 씬 1) | ☐ | |
| ③ | 전역 쓰기 0건 | ☐ | |
| ④ | 세션 로그 5개 이상, 날짜 3일 이상, `999_retrospective.md` 있음 | ☐ | 미달 → 두 과목 로그 상한 5점 |
| ⑤ | 게임 1회 실행: 타이틀 → 새 씬 → 플레이(웨이브 · 적 3종) → 결과 → 재실행 시 하이스코어 유지 | ☐ | |
| ⑥ | `waves.txt` 한 줄을 일부러 깨뜨려 실행 → 줄 번호 포함 에러 | ☐ | 조용히 무시하면 R2 불인정 |
| ⑦ | 저장 파일을 깨뜨려 실행 → 죽지 않고 기본값 | ☐ | R6 |
| ⑧ | 출발 코드(A/B)와 출처 표 대조. 출발 코드에 이미 있던 기능을 요건 · 가산으로 내세우지 않았나 | ☐ | |

### 로그 대조 (시연 대체)
- [ ] 로그의 커밋 해시 3개를 무작위로 골라 `docs/git_log.txt` 에 있는지, 시간 순서가 맞는지 확인
- [ ] 큰 코드 변경 커밋(`--stat` 상위 3개)에 대응하는 프롬프트 기록이 있는지 확인. 없으면 "로그 없는 대량 생성"으로 메모
- [ ] (선택) 프롬프트 1개를 같은 첨부 · 같은 도구로 재실행해 결과 성격이 비슷한지 확인
- [ ] 필수 기록 3종: AI 오류 포착 2건(Lua 1 · 구조 1), 경계 위반 거절(`layer_check` 원문), 명세 기반 프롬프트

## 자주 나올 판정 기준

| 상황 | 처리 |
|---|---|
| README 명령으로 실행 불가 | 안내 후 재제출 1회. 재제출도 불가하면 기능 항목 0 |
| 로그 해시가 `git_log.txt` 에 없음 | 건당 해당 과목 로그 −1 (최대 −3) |
| 마감 전날에 세션 대부분이 몰림 | 날짜 3일 요건 미달로 보고 로그 상한 5점 |
| 대량 코드 커밋에 대응 프롬프트 없음 | 개선 이력 항목 최대 1점 |
| 설명 문항이 공통 설명이고 학생 코드와 무관 | 해당 문항 0 |
| 출처 표에 없는 공개 예제 재사용 발견 | 해당 기능 불인정, 정도에 따라 학사 규정 |
