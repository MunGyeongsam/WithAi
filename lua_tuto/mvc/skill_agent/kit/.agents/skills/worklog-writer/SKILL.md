# 목적

기말과제의 **AI 협업 로그** 채점 항목(프롬프트 원문, 개선 이력, 거절·수정 사례, 회고)을 빠짐없이 남기게 한다.

# 절차

1. 이번 세션 대화에서 사용자가 보낸 프롬프트를 찾는다. **원문을 요약하거나 고치지 말고 그대로** 옮긴다.
2. 각 프롬프트마다 AI 결과와 판정(채택 / 수정 후 채택 / 거절)을 적는다.
3. 판정이 "수정 후 채택" 또는 "거절"이면 문제점과 다음 프롬프트에서 바꾼 점을 적는다.
4. 사용자에게 커밋 해시를 물어 채운다. 모르면 `(커밋 전)` 으로 둔다.
5. 마지막에 다음 세션용 인계 메모를 10줄 이내로 쓴다.
6. 사용자가 직접 확인하지 않은 내용(예: 테스트 통과 여부)은 지어내지 않고 `(확인 필요)` 로 둔다.

# 하지 말 것

- 실패나 거절 기록을 빼거나 미화하지 않는다. 실패 기록이 채점에서 더 중요하다.
- 하지 않은 작업을 했다고 쓰지 않는다.
- 코드 전문을 로그에 넣지 않는다. 파일 경로와 함수 이름만 쓴다.

# 출력 형식

```markdown
# NNN - YYYY-MM-DD - 세션 제목

## 세션 목표
- (한 문장)

## 프롬프트 기록 #N
- 시각 / 커밋: HH:MM / abc1234
- 도구: Gemini 앱 / Antigravity (사용한 스킬·에이전트)
- 목적:
- 프롬프트 원문:
  > (그대로)
- AI 결과 요약:
- 판정: 채택 / 수정 후 채택 / 거절
- 문제점: (파일:줄, 무엇이 왜 틀렸나)
- 다음 프롬프트에서 바꾼 점:

## 검증
- 테스트 명령과 결과:
- 실행 확인(필요 시 1회):

## 회고
- AI 에 맡긴 것 / 내가 직접 한 것:
- 다음에 프롬프트를 다르게 쓸 점:

## 인계 메모 (다음 세션 첫 프롬프트에 붙여넣기)
1) 완료 2) 바뀐 파일·핵심 함수 3) 정한 규칙 4) 남은 문제 5) 다음 태스크
```
