# 2주차 — [실습 1] 겔러그 모놀리식 (고통 체감)

> **소요:** 8시간 (실습 중심)
> **선행:** 1주차(메타테이블, 게임 루프, 고정 타임스텝).
> **이번 주 한 문장:** 구조 없는 단일 파일로 겔러그를 만들고, **"왜 아키텍처가 필요한가"를 몸으로 느낀다.**

---

## 🎯 학습 목표

1. 입력·물리·적 패턴·탄막·충돌·렌더·연출·상태를 **한 파일(`main.lua`)에 몰아넣어** 동작하는 게임을 만든다.
2. 코드가 커질수록 생기는 **구체적 고통**(결합·테스트 불가·수정 전파·AI 컨텍스트 오염)을 **기록**한다.
3. 기능 추가(유도 미사일/보스 탄막) 시 **스파게티 현상**을 직접 겪고 숫자로 남긴다.

> ⚠️ **중요:** 이번 주 코드는 **의도적 안티패턴**이다. 잘 만드는 게 목표가 아니라 **잘못된 구조의 비용을 체감**하는 게 목표다. 워크스페이스의 "암묵적 전역 금지/결정성" 규칙을 **일부러** 어기는 지점이 있고, 그 지점이 바로 다음 주 리팩터링의 재료가 된다.

## 1. 모놀리식으로 만들기 (2.5h + 2.0h)

### 1-1. "모놀리식"이란?
- 모듈 분리 없음. **파일 하나**에 모든 책임이 산다.
- 상태는 **파일 전역 변수 덩어리** 하나로 관리.
- `update`가 입력·물리·충돌·연출·사운드를 **한 함수에서** 처리.

### 1-2. 구현 순서(권장)
1. 플레이어 사각형 + 좌우 이동 + 화면 경계 클램프
2. Space 발사(쿨다운) + 총알 위로 이동
3. 적 편대(그리드) 생성 + 좌우 이동 + 끝에서 한 칸 하강
4. 적 랜덤 발사 + 적 총알 아래로 이동
5. 충돌: 내 총알×적(점수+파괴), 적 총알×플레이어(라이프 감소)
6. 연출: 파괴 파티클, 화면 번쩍임(flash), 피격 시 화면 흔들림(shake)
7. HUD(점수/라이프) + 게임오버/재시작

> **참고 구현:** [examples/galaga_monolith/main.lua](examples/galaga_monolith/main.lua)
> 먼저 직접 작성하고, 막히면 참고 구현과 대조한다.

### 1-3. 바이브 코딩 메모
- AI에게 "적 편대가 좌우로 움직이다 끝에서 내려오게 해줘"처럼 요청해 빠르게 채운다.
- **관찰 포인트:** 파일이 길어질수록 AI가 **엉뚱한 변수**를 건드리거나, **이미 있는 로직을 중복 생성**하기 시작한다. 이 순간을 메모한다.

## 2. 이 코드가 품은 "고통" 해부 (관찰 1.0h)

참고 구현에는 `⚠️` 주석으로 **고통 지점**을 표시해 두었다. 핵심 네 가지:

### ❶ Model-View 결합 (가장 중요)
충돌 판정(로직) 한복판에서 **연출/사운드를 직접 호출**한다.
```lua
if e.alive and hit(b, e) then
  e.alive = false
  score = score + 100
  explode(e.x + e.w*0.5, e.y + e.h*0.5)  -- ⚠️ 로직이 파티클·flash·사운드를 직접 생성
  ...
```
→ "적이 죽는 **규칙**"과 "적이 죽을 때 **보이는 것**"이 한 덩어리. 하나를 바꾸면 다른 하나가 휘말린다.

### ❷ 헤드리스 테스트 불가
`main.lua`는 `love.*`(graphics/keyboard/audio) 없이는 **require조차 안 된다.**
```
love 없이 로직만 테스트?  →  불가능.
"총알 1,000개가 적과 충돌 시 점수 계산이 맞는가"를 창 없이 0.1초에 검증할 방법이 없다.
```
→ 모든 검증이 "창 띄워 눈으로"에 의존. 느리고 비재현적.

### ❸ 비결정성
```lua
math.randomseed(os.time())   -- ⚠️ 매 실행 다른 결과
love.update(dt)              -- ⚠️ 고정 스텝 없이 raw dt 적분
```
→ 같은 입력도 결과가 매번 다름. 버그 재현·리플레이·자동 테스트가 모두 어렵다. (1주차에서 배운 고정 타임스텝이 여기선 증발)

### ❹ 수정 전파 & 매직 넘버
- 화면 폭 `600`, 적 간격 `60`, 쿨다운 `0.25` … 상수가 **여기저기 흩어져** 한 값을 바꾸려면 여러 곳을 찾아야 한다.
- 상태가 전부 파일 전역이라 **어디서 누가 바꾸는지** 추적이 어렵다.

## 3. 기능 추가로 스파게티 터뜨리기 (실습 1.5h + 기록 1.0h)

아래 중 **하나**를 골라 추가하고, **건드린 위치 수**를 세어 기록한다.

### 과제 A — 유도 미사일(Homing Missile)
- 요구: 특정 키로 발사된 미사일이 가장 가까운 적을 향해 **휜다**.
- 예상 전파: 총알 자료구조(미사일 플래그 추가) → 총알 이동 루프(유도 분기) → 충돌 루프(미사일도 처리) → 그리기(다른 색) → 입력(새 키). **최소 5곳.**

### 과제 B — 보스 탄막(Bullet Pattern)
- 요구: 일정 점수 이상이면 보스 등장, **원형/부채꼴 탄막**을 뿌린다.
- 예상 전파: 적 자료구조(보스 HP) → 편대 로직(보스 분기) → 적 발사 로직(패턴 생성) → 충돌(보스 다중 피격) → 그리기 → 상태(보스전 플래그). **최소 6곳.**

### 기록 양식 (→ `monolith_pain.md`)
- 추가한 기능과 **건드린 함수/블록 목록**
- 그 과정에서 **깨진 것**(예: 유도 로직이 일반 총알까지 휘게 함)
- 디버깅에 걸린 체감 난이도(1~5)
- AI 프롬프트가 **오염된 순간**(엉뚱한 변수 수정, 중복 생성 등)

> 이 숫자들이 **4주차에서 MVC와 정량 비교**하는 기준선이 된다.

### 강사용 "이렇게 터진다" 시연본
기능 추가(유도 미사일 **+** 보스 탄막)를 실제로 끼워 넣은 **완성 버전**이 있다:
[examples/galaga_monolith_full/main.lua](examples/galaga_monolith_full/main.lua)

- 각 추가 지점에 `[H*]`(유도 미사일)·`[B*]`(보스) **전파 마커**를 달아 두었다.
- 기본판과 비교하면, 작은 기능 2개가 **파일 전역에 번진** 모습을 한눈에 볼 수 있다.

**전파 지점 요약 (왜 아픈가):**
| 기능 | 전파된 곳 | 수 |
|------|----------|----|
| 유도 미사일 | 상수·총알 자료구조·발사 입력·총알 이동(유도 분기)·목표 탐색 함수·그리기 색상 | 약 6곳 |
| 보스 탄막 | 상태 변수·reset·등장 조건·보스 이동/발사·적 총알 자료구조·적 총알 이동·충돌(보스 HP)·그리기/HP바·승리 처리 | 약 9곳 |

> 핵심 메시지: **"기능은 2개인데 수정은 15곳."** 책임이 섞여 있어 한 기능이 파일 전체로 샌다.
> 이걸 비교용으로 보여주되, **학생은 기본판에서 직접 겪게** 하는 것이 학습 효과가 크다.

> 📄 번짐을 수치로 정리한 분석 문서: [번짐_분석_완성본.md](번짐_분석_완성본.md)
> (기본판 280줄 → 완성본 418줄, 변경 블록 **23곳**에 흩어짐)
