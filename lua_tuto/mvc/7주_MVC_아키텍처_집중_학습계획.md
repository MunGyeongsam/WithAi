# Lua & LÖVE2D MVC 아키텍처 집중 학습 계획 (7주 · 깊이 우선 A안)

> **구성:** 7주 / 주 1일 / 1일 8시간 = **총 56시간**
> **방식:** 모든 게임을 **처음부터 직접 구현**한다. (기존 코드 재활용 안 함)
> **주력 소재:** 전통 **겔러그식 슈터**를 ① 모놀리식으로, ② MVC로 **두 번** 만들어 같은 게임을 아키텍처별로 대비한다.
> **보조 소재:** **Pong**(루프 워밍업), **Snake**(Flux/중앙 Store 체험) 각 1개만 — **깊이 우선**이므로 추가 게임은 최소화한다.
> **핵심 목표:** 게임에서의 MVC(*Model 이 View 를 모르는 MVC + 매 프레임 읽기(Pull) 갱신*)를 직접 구현·체감·검증하여 이해한다.
> **사전 학습(필수, 8시간 외):** [basics/](basics/README.md) — LÖVE2D 없이 콘솔 예제 6개로 M/V/C 역할부터 익힌다(약 3~4시간). **1주차 전에 완료**하는 것을 전제로 2·3주차가 basics 를 참조한다.

---

## 📌 설계 원칙 (리포트 교정 반영)

1. **용어 정확화** — 본 과정의 "MVC"는 고전 MVC 와 역할·의존성이 같고, **갱신만 통지(Push) 대신 매 프레임 읽기(Pull)**다. Passive View/MVP 가 아니다(이전 판 표기 정정, week03 1-3절).
2. **프레임 독립성** — "60fps 연산"이 아니라 **dt 기반 고정 타임스텝(fixed timestep) + 가변 렌더링**으로 구분한다.
3. **같은 게임 두 번** — 겔러그 모놀리식 → 겔러그 MVC로 **동일 게임**을 비교해 "고통 → 해방"을 선명하게 체감한다.
4. **깊이 우선** — 추가 게임(Pong·Snake)은 각 1일 스파이크로 최소화하고, 겔러그 MVC·헤드리스 테스트에 시간을 집중한다.
5. **매일 산출물 + 검증 기준** — 추상적 "비교"가 아니라 측정 가능한 결과물로 마무리한다.

### 6주차 — 단방향 흐름(Flux): Snake 처음부터 + 겔러그 리플레이
**학습 목표:** "고쳐서 vs 처음부터 잘"을 대비한다. Snake를 **처음부터 Flux**(Action → Dispatcher → Store, 순수 리듀서, 시간도 Action)로 만들고, 겔러그에는 **Model 수정 0줄**로 입력 기록·리플레이를 붙인다. 리플레이가 해결하는 것(일어난 판의 재현)과 못 하는 것(실시간 입력 양자화, 4주차 `[한계]`)을 구분한다.

| 시간 | 블록 | 내용 |
|------|------|------|
| 1.0h | 개념 | Flux 4부품, 순수 리듀서(옛 state 보존 = 시간 여행), 시간도 Action, Pull 갱신 MVC 와의 차이 |
| 0.5h | 설계 | Action 계약(시드도 Action 에), Dispatcher 규칙(검증·중첩 금지), love 를 모르는 `App` 조립, 계층 규칙 |
| 2.0h | 실습 1 | `snakeReducer` `turn`·`tick` → `reducer_test` |
| 1.0h | 실습 2 | `Dispatcher` 전달 루프, `ActionLog` record(복사)·replay → `flux_test` |
| 1.5h | 실습 3 | 겔러그 `InputRecorder`(스텝마다, 복사 — 재사용 테이블 함정) + `ReplayScene`(배속) → `replay_test` |
| 0.5h | 실습 | 실행 확인 1회씩 (Snake·겔러그 한 판 → V) |
| 1.5h | 비교·회고 | `[한계, 그대로]` 토론, 겔러그(고쳐서) vs Snake(처음부터) 비교표, 퀴즈 |

- **산출물:** 리플레이되는 Snake(Flux) + 리플레이되는 겔러그 + 비교 메모
- **검증:** `layer_check`(Snake·겔러그)·`reducer_test`(18)·`flux_test`(18)·`replay_test`(9) 통과, `love` 실행 각 1회
- **부수 정정:** 3~6주차 테스트 러너의 `res ~= false`(nil 도 통과) → `res == true`. 4주차 문서의 "기록이 `[한계]` 를 해결" 서술 정정

1. **엄격한 계층 분리** — Model/View/Controller를 파일 단위로 명확히 구분해 AI가 올바른 영역만 수정하게 한다.
2. **명시적 인터페이스(Docstring)** — 동적 타입 Lua에서 데이터 테이블 구조를 주석으로 서술해 할루시네이션을 줄인다.
3. **작은 컨텍스트 파일** — "줄 수"가 아니라 **"단일 책임"** 기준으로 쪼갠다. (150~200줄은 참고치일 뿐 절대 규칙 아님)

## 📎 검증 정책 (워크스페이스 공통)

- **테스트 하네스 우선:** 단위·모듈·시뮬레이션 검증을 기본으로 한다.
- **전체 실행은 최소화:** 입력/렌더/프레임 타이밍 확인이 필요할 때만 task `Love2D: Run project`로 1회 실행한다.
- **결정성 유지:** 동일 시드·동일 입력 → 동일 결과를 보장하도록 숨은 프레임 부수효과를 피한다.
