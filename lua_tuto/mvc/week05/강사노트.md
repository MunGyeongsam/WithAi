## 2. 시간이 밀릴 때 줄이는 순서
1. `PlayScene` TODO → 완성본 복사 허용(로직이 4주차 main 과 같다).
2. 과제의 "새 단계(BossRagePhase)" → 숙제로.
3. 5절 실측 → 숫자 표만 보여 주고 토론 축소.
- **줄이면 안 되는 것:** 1-3 두 층의 상태, `equivalence_test` 를 통과시키는 경험, 5절 ⚠️ 3개.

## 3. 시연: 순환 require 를 직접 터뜨리기 (5분)
`TitleScene.lua` 맨 위에 `local PlayScene = require("PlayScene")`, `PlayScene.lua` 에 `require("ResultScene")`, `ResultScene.lua` 에 `require("TitleScene")` 을 넣고 실행 → `loop or previous error loading module` 류의 에러(또는 nil 참조). "그래서 조립부가 목록을 넣어 준다." `layer_check` 도 씬끼리 require 를 잡는다는 걸 이어서 보여 준다.

## 4. equivalence_test 운영 팁
- 학생이 `BossPhase` 를 채운 뒤 `phase_test` 는 통과하는데 `equivalence_test` 만 실패하는 경우가 **가장 교육적**이다. 작성자가 직접 변이를 넣어 확인한 결과:

| 변이 | 잡는 테스트 | 비고 |
|------|-------------|------|
| 전환 스텝의 `boss:update` 한 줄 삭제 | `equivalence_test` 8개 전부 (200번째 스텝 전후) | 4-2 💡 의 사례 |
| 격파 시 `boss_destroyed` 를 `boss_hit` **앞에** 발행 | `equivalence_test` 모든 판의 격파 스텝 | 이벤트 **순서**도 비교 대상 |
| `takeDamage` 호출을 `boss_hit` 발행 앞으로만 옮김 | 잡지 않음 (정상) | 관찰 가능한 결과가 같으므로 **바뀜 없음**이 맞다 |
| 격파 후 `break` 누락 | **`equivalence_test` 는 못 잡음** → `phase_test` "총알 3발 동시" 가 잡음 | 아래 교훈 |

- **교훈 (학생에게 그대로 전할 것):** 무작위 시뮬레이션 비교는 강력하지만 **드문 경계 상황**(격파 스텝에 총알 2발 이상 동시 명중)은 거의 만나지 못한다. 그래서 경계 상황은 **일부러 만드는 단위 테스트**로 고정한다. 두 종류의 테스트는 서로를 대신하지 않는다. (초판에는 이 테스트가 없었고, 변이 검사 중에 발견해 추가했다.)
- 실패 메시지의 "N번째 스텝"을 보고 **그 스텝까지 시뮬레이션해 두 버전의 이벤트를 출력**해 보게 한다(디버깅 연습).
- 이 테스트는 4주차 폴더를 상대 경로로 읽는다. 학생이 폴더를 옮기면 "module not found" 가 난다.

## 5. 예상 질문
| 질문 | 답의 방향 |
|------|----------|
| "`game.state`(playing/gameover/won)도 State 패턴으로 바꿔야 하나요?" | 지금은 **결과 표시용 값**이라 문자열로 충분하다. 상태마다 **행동(규칙)이 달라질 때** 객체로 바꾼다. 패턴은 필요할 때. |
| "단계가 2개뿐인데 과하지 않나요?" | 맞는 지적. 2개면 `if` 도 괜찮다. 판단 기준: 같은 상태에 대한 `if` 가 **여러 파일·여러 함수에 흩어졌는가**. 4주차는 4곳이었다. |
| "씬이 Model 을 만들면 씬이 Model 을 아는 거 아닌가요?" | 씬은 **조립 계층**이다(4주차 main 의 역할을 나눠 가진 것). 조립 계층은 M·V·C 를 모두 아는 게 정상. 금지는 Model 이 씬·View 를 아는 것. |
| "hump.gamestate 쓰면 되지 않나요?" | 써도 된다. 오늘 만든 `SceneStack` 과 같은 일을 한다. 원리를 알고 쓰면 `transparent` 같은 확장이 필요할 때 막히지 않는다. |
| "FormationPhase 에서 BossPhase 를 require 하는 건 순환 아닌가요?" | BossPhase 는 FormationPhase 를 모르므로 순환이 아니다. 보스전 → 편대전으로 되돌아가는 전환이 생기면 그때 씬처럼 목록 주입이 필요해진다. |

## 6. 개념 퀴즈 정답 & 채점 포인트 (README 8절)

**1. 상태 객체 / context**
- 상태 객체: `FormationPhase`, `BossPhase` (씬 층에서는 각 Scene). context: `GameModel` (씬 층에서는 `SceneStack`).
- 공통 규칙(이동·발사·공통 충돌)은 context, 상태별 규칙(보스 피격·편대 재생성)은 상태 객체.

**2. 단순 FSM 의 일시정지 문제**
- Play → Pause 로 바꾸면 Play 가 사라지므로 게임 상태를 따로 저장·복원해야 한다. 스택은 Play 를 아래에 살려 두고 update 만 멈춘다 → pop 하면 그대로 이어진다.

**3. 일시정지 = 씬인 이유**
- 진행 단계는 **결정성이 필요한 게임 규칙**(리플레이·테스트 대상)이고, 일시정지는 사람의 앱 조작이다. Model 에 넣으면 모든 규칙이 "일시정지면?"을 알아야 한다. 씬이면 Model 은 그냥 **불리지 않을** 뿐이다.
- ❌ 감점: "일시정지도 상태니까 Model 에" — 두 층을 구분하지 못함.

**4. ctx.scenes 가 없으면**
- 씬끼리 서로 require → 순환 require 로 로드 실패(또는 nil). 테스트에서 가짜 씬으로 바꿔 끼우기도 어려워진다.

**5. 보스전 포함 검사 이유**
- 편대전 구간만 비교하면 `BossPhase` 를 아무렇게나 짜도 통과한다. **테스트가 검사하려는 코드가 실제로 실행됐는지**(커버리지)를 같이 확인해야 의미가 있다. 4주차 "빈 코드도 통과하는 금지 테스트"와 같은 교훈.

**6. 보스 3줄**
- 유도 미사일 표적 선정(`_steerMissiles`)과 `reset` 의 `boss = nil`. 단계와 무관한 **"표적이 될 수 있는 엔티티 목록"** 문제라 State 패턴의 축이 아니다.

## 7. 자주 막히는 곳
- **`push` 에서 `scene.stack = self` 를 빠뜨림**: 씬이 `self.stack:push(...)` 할 때 nil 에러. 테스트 메시지가 `attempt to index field 'stack'` 이면 이것.
- **`draw` 에서 투명 씬 탐색을 아래에서부터 함**: 항상 맨 아래부터 다 그려 Title 이 게임 뒤에 깔린다. "맨 위에서 내려가며 첫 불투명"이 정답.
- **`PauseScene.transparent` 를 인스턴스 필드로 `init` 에서 넣음**: 동작은 한다. 클래스 필드로 두는 게 "이 종류의 씬은 항상 투명"이라는 의미를 더 잘 드러낸다.
- **결과 push 를 매 프레임 함**: SceneStack 이 맨 위만 update 하면 저절로 1회가 된다. 학생이 모든 씬을 update 하게 만들었다면 여기서 결과가 무한히 쌓인다 → 3-1 의 교훈으로 연결.

## 8. 실행 확인 기록 (작성자 검증)
- 실제 LÖVE 11.5(macOS)에서 스크립트로 키를 넣어 Title > Play > Pause > Play > Pause > Title 경로 160프레임을 오류 없이 통과했다.
- 이때 백그라운드 실행 두 개가 같은 임시 폴더를 지워 첫 시도가 꼬였다. **실행 검증은 한 번에 하나, 고유 폴더, 하드 타임아웃**으로 할 것.
