## 1. 기본 원칙

- **분량**: 1~2쪽. 길게 쓰지 말고 근거 위주로 씁니다.
- **근거**: 모든 주장에 파일명, 코드, 실행 출력 중 하나를 붙입니다.
- **본인 문장**: AI 답변을 그대로 붙이지 않습니다. 특히 5번 설명 문항.
- **사실대로**: 제출 코드와 다르게 쓰면 감점됩니다. (예: 고친 파일을 "안 고침" 으로 적음)

## 2. 항목별 작성법

| 항목 | 무엇을 쓰나 | 채점 포인트 |
|---|---|---|
| 1) 파일 변경표 | 문제별 새 파일 / 고친 파일 / 고치지 않은 주요 파일 | 실제 변경 내역과 일치하는가 |
| 2) 핵심 프롬프트 | 실제로 AI 에게 보낸 프롬프트 3~5개 (요약 가능) | 제약조건을 AI 에게 전달했는가 |
| 3) AI 실수 사례 | AI 가 만든 코드 → 어긴 규칙 → 발견 방법 → 고친 코드 | 코드 근거가 있는가 |
| 4) 테스트 결과 | 구현 전 FAIL, 구현 후 ok 출력 붙여 넣기 | 테스트를 먼저 썼는가 |
| 5) 설명 문항 | Q1~Q3 답, 각 3~5줄 | 이 프로젝트의 파일·이벤트 이름으로 설명했는가 |

### 작성 팁

- **변경 파일 확인**
  - git 사용 시: `git diff --stat`
  - git 미사용 시: VS Code 탐색기에서 원본 파일과 수정 파일을 선택 → 우클릭 → "선택 항목 비교"
- **AI 실수 찾기**: AI 는 "기존 메서드 수정 금지", "다른 Model 을 모르게" 같은 제약을 자주 어깁니다.
  받은 코드를 붙이기 전에 **어떤 파일의 어떤 함수가 바뀌는지** 읽어 보세요.
- **테스트 전/후**: 구현 전에 테스트를 먼저 추가하고 한 번 실행해 출력을 저장해 두세요.
  아직 없는 모듈을 `require` 해서 오류로 멈춘다면, 그 오류 메시지를 "구현 전" 결과로 붙여도 됩니다.

---

### REPORT — 홍길동 (20250000)

#### 1) 파일 변경표

| 문제 | 새 파일 | 고친 파일 | 고치지 않은 주요 파일 |
|---|---|---|---|
| 예시 | `views/remaining_view.lua` | `main.lua` (위젯·레이아웃 등록 2줄), `tests/dungeon_test.lua` | `models/` 전부, `controllers/` 전부 |

한 줄 이유: 남은 방 수는 `DungeonModel` 에 이미 있는 값(`rooms`, `index`)을 읽기만 하면 되므로 Model 은 고칠 필요가 없었다.

#### 2) 핵심 프롬프트

1. "06_dungeon 의 README 3장 의존성 표를 지켜. View 는 Model 을 읽기만 하고, models/ 와 controllers/ 는 수정하지 마."
2. "남은 방 수를 보여주는 위젯을 만들어. 기존 위젯처럼 title 과 lines(game) 규약을 따라."
3. "구현 전에 tests/dungeon_test.lua 에 실패하는 테스트부터 써 줘."
4. (실수 발견 후) "View 안에서 dungeon:advance() 를 호출하지 마. 상태를 바꾸지 말고 계산만 해."

#### 3) AI 실수 사례

**AI 가 만든 코드**

```lua
function RemainingView:lines(game)
  local room = game.dungeon:advance() -- 방을 실제로 이동시킴
  ...
end
```

**어긴 규칙**: "View 는 Model 을 읽기만 한다."

**발견 방법**: 자동 시연에서 방 번호가 2씩 건너뛰는 것을 보고, 바뀐 파일을 다시 읽어 `advance()` 호출을 찾았다.

**고친 코드**

```lua
function RemainingView:lines(game)
  local dungeon = game.dungeon
  return { string.format("남은 방: %d", #dungeon.rooms - dungeon.index) }
end
```

#### 4) 테스트 결과

구현 전

```
  FAIL - 시작 시 남은 방 7
  FAIL - 1칸 이동 후 남은 방 6
결과: 56 통과, 2 실패
```

구현 후

```
  ok   - 시작 시 남은 방 7
  ok   - 1칸 이동 후 남은 방 6
결과: 58 통과, 0 실패
```

#### 5) 설명 문항 (예시 질문: "로그 문구를 영어로 바꾸려면 어느 파일을 고치나?")

**좋은 답** ✅

> `log_view.lua` 의 `FORMAT` 표만 영어로 바꾼 `log_view_en.lua` 를 만들고, `main.lua` 에서 `LogView` 대신 등록하면 된다.
> `LogModel` 은 문장이 아니라 `{ type, data }` 원본만 저장하기 때문에 Model 은 고칠 필요가 없다.
> Controller 도 화면 문구를 모르므로 그대로다.

**부족한 답** ❌

> MVC 는 Model, View, Controller 가 분리되어 있어서 View 만 바꾸면 된다.

→ 일반론이고, 이 프로젝트의 파일명·구조를 근거로 들지 않았다.
