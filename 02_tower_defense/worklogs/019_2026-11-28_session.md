## 목표

- 기존 도메인 객체 참조를 담는 최소 `GameState`를 추가한다.
- 구조화된 `CommandResult` 생성 계약을 추가한다.
- Command enqueue FIFO, drain snapshot, handler 디스패치를 구현한다.
- reject·invalid·duplicate Command의 상태 불변과 revision 소유를 검증한다.
- Processor가 `tick`과 `revision`을 직접 증가시키지 않도록 제한한다.
- Transaction, Scene, 입력, UI, 기존 도메인 동작을 변경하지 않는다.

## 범위

### 변경 허용

- Command Processor headless harness
- 기존 전체 runner의 최소 연결
- 상태 문서와 현재 worklog

- Transaction preview/commit/reject
- GameplayScene, GameMap, Pathfinder, Enemy, Economy, Tower, WaveManager

- 다른 프로젝트

## 결정

| 결정 | 근거 | 상태 |
|---|---|---|

| Processor는 handler 디스패치와 queue만 소유한다. | revision·tick·phase 변경권은 GameState/handler 또는 Transaction에 남긴다. | 완료 |
| drain 시작에 queue와 중복 추적을 스왑한다. | drain 중 enqueue된 Command가 다음 drain으로 남고 원래 FIFO 스냅샷은 변하지 않는다. | 완료 |
| pending queue의 중복 객체·ID만 거절한다. | 이전 drain ID 이력은 Processor가 보관하지 않고 Command 생성기의 단조 증가에 맡긴다. | 완료 |
