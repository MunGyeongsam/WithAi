## 결정

| 결정 | 근거 | 상태 |
|---|---|---|
| 결정적 Simulation Core를 중심 상태·규칙 실행기로 둔다. | 같은 Command와 fixed step에서 같은 게임 결과를 만들고 헤드리스 검증을 가능하게 한다. | 확정 |
| 배치·제거·판매·업그레이드·웨이브 시작은 Command/Transaction으로 처리한다. | 맵·골드·적 경로의 부분 적용을 막는다. | 확정 |

| ECS, 전역 Event Bus, Service Locator, 완전한 Event Sourcing은 도입하지 않는다. | 현재 핵심 문제를 직접 해결하지 않고 구조 비용을 키운다. | 확정 |

## 미해결 문제와 위험

- 상세 설계는 파일과 계약을 정의했지만 M1 characterization 대상의 현재
  관찰 가능한 계약을 아직 코드별 체크리스트로 분해하지 않았다.
- `GameState`/ViewData의 참조 직접 노출 허용은 초기 성능을 위한 임시 선택이며
  View가 수정하지 않는다는 정적·하네스 검증이 필요하다.
- 현재 `Enemy:updatePath`는 새 문서의 안전 합류 규칙을 충족하지 않는다. 수정은
  M2 경로 편집 원자성 구현에서 characterization 뒤에 진행한다.
- ADR 상세 설계가 확정됐으므로 다음 단계에서 구조 전체를 한 번에 재작성하지
  않고 하나의 행동 경계만 이동해야 한다.
- 프레임 입력 snapshot과 fixed-step Command 처리의 시점은 현재와 달라질 수
  있으므로 M1에서 현재 동작을 먼저 기록하고 migration에서 보존 또는 승인된
  변경 여부를 명시해야 한다.
