```text
[단일 목표]
TD-M2-001 minimal GameState/CommandResult/CommandProcessor 경계를 구현한다.

[필수 참조]
1. 02_tower_defense/worklogs/018_2026-11-28_session.md

4. 02_tower_defense/docs/planning/TD-PLAN-002-M2-path-edit-atomicity-plan.md
5. 02_tower_defense/docs/architecture/002-deterministic-simulation-command-architecture.md의
   GameState, Command, CommandResult 계약

[허용 범위]
- 최소 GameState·CommandResult·CommandProcessor 신규 모듈
- 해당 module harness
- 전체 M1 runner 연결에 꼭 필요한 최소 runner 수정
- SESSION-STATUS와 새 worklog

[필수 계약]
- GameState는 기존 map/economy/enemies/towers/wave 객체를 참조로 보관하고
  revision/tick/phase/nextEntityId를 갖는다. Command ID는 Processor 밖의
  생성기가 단조 증가시킨다.
- CommandProcessor는 enqueue 순서 FIFO로 handler를 실행한다.
- 결과는 commandId, accepted, code, revision, events를 포함한다.
- reject와 INVALID_COMMAND는 GameState fingerprint와 revision을 바꾸지 않는다.
- accepted commit처럼 동작하는 fixture handler로 revision 증가가 관찰된다.
- drain은 시작 시점 queue snapshot을 FIFO 처리하고 실행 중 추가된 명령은 다음
  drain에 남긴다. Processor는 tick과 revision을 직접 증가시키지 않는다.
- Command는 명시적 ID를 보존하며 같은 pending queue의 중복 ID는
  INVALID_COMMAND다. 이전 drain ID 이력은 Processor에 보관하지 않는다.

[제약]
- Transaction preview/commit/reject 구현을 시작하지 않는다.
- gameplayScene, GameMap, Pathfinder, Enemy, Economy, Tower, WaveManager의
  동작을 바꾸지 않는다.
- 밸런스, UI, 입력, 렌더링, 웨이브, Wave 10 victory를 수정하지 않는다.

[완료 기준]
- 새 harness의 FIFO·성공·reject·invalid Command 사례가 Lua 5.1에서 통과한다.
- M1 runner가 14 harness·79 사례 그대로 통과한다.
- LuaJIT 검증, git diff --check, 새 worklog와 상태 인계가 완료된다.
- 전체 LÖVE 실행은 미실행 사유와 함께 기록한다.
```
