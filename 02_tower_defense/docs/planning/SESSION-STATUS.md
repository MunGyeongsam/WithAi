## 목적

이 문서는 세션 사이에 이어받을 현재 상태와 다음 행동을 한곳에 유지한다.
이미 끝난 결정의 근거, 실제 변경, 검증 결과는
[worklogs](../../worklogs/)에만 기록한다.

## 문서 역할 분리

| 문서 | 원본으로 유지하는 정보 | 기록하지 않는 정보 |
|---|---|---|
| `SESSION-STATUS.md` | 현재 작업 상태, 우선순위, 의존성, 차단 요소, 다음 세션 대상 | 상세 결정 근거, 실행 이력, 검증 결과, 프롬프트 전문 |
| 최신 worklog | 이번 세션의 실제 결정·변경·검증·회고, 다음 세션 프롬프트 | 미래 작업을 이미 완료한 것처럼 표시한 정보 |
| GDD/ADR/작업 계획 | 각 문서의 설계·결정·작업 범위 | 세션별 실시간 진행 현황 |

동일한 사실은 현재 상태가 필요한 경우에만 이 문서에 유지하고,
이력은 worklog에서 삭제하거나 다시 쓰지 않는다.

### 상태 정의

- `대기`: 선행 조건이나 세션 배정을 기다리는 현재 작업
- `진행 중`: 한 세션에서 실제로 작업 중인 항목
- `검증 중`: 산출물은 만들었으나 완료 기준을 확인하는 중
- `완료`: 완료 기준과 검증 결과가 worklog에 기록됨
- `보류`: 차단 요소나 사용자 결정이 있어 다음 행동을 진행할 수 없음
- `중단`: 더 이상 진행하지 않기로 명시적으로 결정됨

동시에 `진행 중` 또는 `검증 중`인 작업은 최대 하나만 둔다.
예외가 필요하면 사유와 해당 작업 ID를 worklog에 남긴다.

## start-session 절차

1. `SESSION-STATUS.md`를 읽어 현재 작업 상태, 차단 요소, 다음 세션 대상을
   확인한다.
2. `worklogs/`에서 파일명의 `<NNN>_YYYY-MM-DD_session.md` 번호가 가장 큰
   worklog를 최신 기록으로 선택한다.
3. 최신 worklog의 `다음 세션 프롬프트`와 앞 세션의 검증 결과·미해결 문제를
   읽는다.
4. 프롬프트와 현재 상태가 충돌하면 현재 상태 문서를 우선 사실로 취급하되,
   충돌을 worklog에 기록하고 프롬프트 범위를 임의로 확장하지 않는다.
5. 대상 작업 ID 하나를 `진행 중`으로 바꾸고 같은 ID를 작업 계획이나 GDD와
   대조한다.
6. 시작 프롬프트의 수정 범위, 완료 기준, 검증 방법이 없으면 작업 시작 전에
   사용자에게 보완을 요청하거나 prompt-improver로 한 문서화된 초안을 만든다.
7. 현재 세션용 새 worklog 번호를 정하고, 기존 worklog를 덮어쓰지 않는다.
8. `src/` 또는 `tests/` 작업은 이번 세션 프롬프트가 명시적으로 허용한
   경우에만 수행한다.

지원되는 환경에서는 `/start-session`을 실행한 뒤 위 절차를 적용한다.
명령 자체는 저장소 공통 절차이므로, tower defense 세션에서는 이 문서와
최신 worklog를 추가 입력으로 사용한다.

## end-session 절차

1. 수행한 변경과 실제 검증 결과를 확인한다. 실행하지 않은 항목은
   `미실행`, 완료하지 못한 항목은 `미완료`로 기록한다.
2. 현재 `SESSION-STATUS.md`에서 작업 상태, 우선순위, 차단 요소, 다음 세션
   대상만 갱신한다. 과거 결정과 상세 검증 내용은 상태 문서에 누적하지 않는다.
3. 현재 세션 번호의 새 worklog를 작성한다. 기존 worklog는 수정하지 않는다.
   필수 항목은 세션 목표, 원문 프롬프트, 결정, 변경 기록, 검증, 미해결 문제,
   인계 메모다.
4. 다음 세션 작업이 있으면 `prompt-improver` 절차를 실행해 다음 프롬프트를
   개선한다. 결과는 해당 세션 worklog의 `다음 세션 프롬프트`에 기록한다.
5. 다음 프롬프트의 원본 위치는 최신 worklog 하나뿐으로 유지한다.
   `SESSION-STATUS.md`에는 프롬프트 본문을 복제하지 않고 최신 worklog 링크만
   둔다.
6. 문서 작업의 범위가 `src/`, `tests/`를 포함하지 않는지 확인한다.
   `git diff --check`를 실행하고 새 문서의 링크와 필수 섹션을 확인한다.
7. `SESSION-STATUS.md`의 `기준 worklog`와 `시작 프롬프트 원본`을 방금 작성한
   worklog로 갱신한다.

지원되는 환경에서는 `/end-session`을 실행한 뒤 위 인계 절차를 적용한다.
저장소 공통 종료 절차의 worklog·검증 단계는 이 문서의 작업 상태 갱신과 새
다음 프롬프트 기록을 포함하도록 확장한다.

## 다음 프롬프트 작성 규칙

`prompt-improver`의 다음 출력 형식을 최신 worklog에 그대로 유지한다.

1. 6요소 진단표: 맥락, 목표, 참조, 제약, 출력 형식, 검증
2. 여러 목표가 섞인 경우 별도 세션 분리 제안
3. 짧은 프롬프트
4. 상세 프롬프트
5. 변경 사유 3줄 이내

프롬프트는 다음 조건을 모두 만족해야 한다.

- 단일 작업 ID와 단일 세션 목표를 명시한다.
- 사용자만 알 수 있는 정보는 추측하지 않고 빈칸 또는 확인 항목으로 남긴다.
- 반드시 읽을 문서와 관련 worklog를 정확한 경로로 적는다.
- 수정 허용 범위와 `src/`, `tests/` 포함 여부를 명시한다.
- 완료 기준과 검증 항목을 관찰 가능한 문장으로 적는다.
- 다음 세션 worklog 작성과 종료 절차 수행을 완료 기준에 포함한다.

`prompt-improver` 결과로 프롬프트를 만든 뒤 작업을 바로 실행하지 않는다.
개선된 프롬프트는 다음 세션의 입력으로만 남긴다.

## 인계 예시

1. 세션 N 종료 시 `TD-001`을 `완료` 또는 `보류`로 갱신한다.
2. 최신 worklog N에 실제 검증 결과와 `TD-002`용 짧은·상세 프롬프트를 남긴다.
3. `SESSION-STATUS.md`의 다음 작업을 `TD-002`, 프롬프트 원본을 worklog N으로
   바꾼다.
4. 세션 N+1은 먼저 상태 문서와 worklog N을 읽고 `TD-002` 하나만
   `진행 중`으로 둔다.
5. 세션 N+1 종료 시 새 worklog N+1을 만들고 다음 프롬프트 원본을 교체한다.

## 갱신 원칙

1. 상태는 실행 전·후 사실을 구분해 적는다.
2. 새로운 TODO는 작업 ID 없이는 추가하지 않는다.
3. 완료된 항목은 상세 근거 대신 완료 상태와 worklog 링크만 남긴다.
4. 보류 항목은 해소에 필요한 결정이나 입력을 차단 요소에 명시한다.
5. 현재 상태와 worklog가 충돌하면 확인 전에는 임의로 복구하지 않고
   현재 세션 worklog에 충돌 사실을 기록한다.
6. 게임 방향, 밸런스, 아키텍처 결정을 이 문서에서 직접 승인하지 않는다.
