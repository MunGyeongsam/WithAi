## 목표

구현 전에 현재 구조를 사실 기반으로 검토하고, 사용할 아키텍처와 패턴 경계를
사용자 승인을 거쳐 확정한다.

## 현황과 갭

### 현재 상태

- `main.lua`가 코어, 입력, 씬 스택, 가상 해상도를 조립한다.
- `gameplayScene`이 전투 결과, 스폰, 경제, 맵 편집, 상태 전이를 함께 조정한다.
- Map/Enemy/Tower 도메인 모듈과 그리기 메서드가 같은 파일에 있다.
- WaveManager가 Enemy를 직접 생성하고 공통 10웨이브 데이터를 내부에 둔다.
- Hud가 씬 전체를 인자로 받아 상태를 직접 읽는다.
- 기본 단위 하네스는 있으나 씬 통합과 원자적 편집 하네스는 없다.

### 이번 작업의 갭

- 각 상태의 단일 소유자가 정의되지 않았다.
- 입력 명령과 Model 변경의 경계가 정의되지 않았다.
- 편집·판매에 적용할 원자적 거래 패턴이 선택되지 않았다.
- View에 전달할 읽기 전용 계약과 허용 의존성이 없다.
- 첫 구현 마일스톤과 작업 순서가 ADR로 연결되지 않았다.

## 작업 순서

1. 현재 모든 Lua 모듈의 상태 소유권과 `require` 관계를 표로 정리한다.
2. ADR-001 선택안 A/B/C를 현재 구조 증거와 비교한다.
3. Command/Transaction 적용 범위와 DTO/View 계약의 최소 범위를 검토한다.
4. 사용자에게 승인/보류/수정 요청이 필요한 결정을 표시한다.
5. M1 첫 리팩터링 작업 계획과 검증 순서를 작성한다.
6. ADR 검토에 사용된 새 아키텍처 용어를 `docs/glossary.md`에 연결한다.
7. 상태 문서와 새 worklog를 갱신한다.

## 완료 기준

- [ ] 현재 상태 소유·의존성 맵이 `src/`의 모든 모듈을 포함한다.
- [ ] Model, Controller, View, Scene, Data/Factory, Command 경계가 문장으로 정의된다.
- [ ] 선택안과 사용하지 않을 패턴의 근거가 ADR에 있다.
- [ ] 새 아키텍처·검증 용어가 용어집에 전체 단어와 프로젝트 예로 기록된다.
- [ ] 사용자가 A/B/C 선택 게이트를 검토하고 마일스톤 순서를 확인하거나 수정한다.
- [ ] `src/`와 `tests/`는 변경되지 않는다.
- [ ] 다음 구현 작업의 파일 목록, 완료 기준, 하네스가 작업 계획에 있다.

## 검증

| 종류 | 실행 항목 | 기대 결과 |
|---|---|---|
| 정적 조사 | `require`, `love.*`, 상태 필드 사용 확인 | 실제 코드 기반 의존성 표 |
| 문서 | ADR-001, M0, 작업 계획 링크 검사 | 끊어진 내부 링크 없음 |
| 범위 | `git status`의 `src/`, `tests/` 확인 | 변경 없음 |
| 문서 품질 | `git diff --check` | 공백 오류 없음 |

- 전체 실행 판정: 불필요
- 판정 근거: 구현이나 입력·렌더링 변경이 없는 구조 검토 세션이다.

## 위험과 대체 경로

| 위험 | 징후 | 대응 |
|---|---|---|
| 패턴 우선 과잉 설계 | 사용처가 없는 추상화가 ADR에 등장 | 현재 GDD 사례를 해결하는 패턴만 유지 |
| MVC 경계가 너무 분산됨 | 한 명령 추적에 5개 이상 파일 필요 | Scene→Model 조정 객체는 제한적으로 허용 |
| 기존 변경과 충돌 | `src/` 사용자가 진행 중 작업 보유 | 이번 세션은 문서만 수행하고 충돌 구현을 미룸 |
| 사용자 승인 전 확정 | ADR이 `수락`으로 기록됨 | `검토 중` 유지하고 질문·선택안 기록 |
