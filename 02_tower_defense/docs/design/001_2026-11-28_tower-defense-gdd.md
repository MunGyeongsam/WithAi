# 001 - 타워 디펜스 첫 GDD

> 상태: 검토 중
>
> 작성일: 2026-11-28
>
> 책임자: Game Director
>
> 기준 문서: [000 - 타워 디펜스 게임 비전](../game/000-vision.md)
>
> 범위: 레벨 1~3 프로토타입의 플레이 경험, 규칙, 콘텐츠와 검증 가설
>
> 주의: 비전은 Review 상태다. 이 문서에서 비전의 승인된 5개 결정은 플레이 규칙으로 구체화하되,
> 비용·위력·보상률·시간 등의 수치는 별도 표시가 없으면 확정값이 아니다.

## 1. 문서 목적

라이트 플레이어가 **벽으로 경로를 만들고, 타워 역할을 조합하며, 웨이브 중 한 칸을 즉시
수정하는 판단**을 한 판 안에서 배울 수 있도록 첫 프로토타입 규칙을 정의한다.

이 문서는 최종 밸런스표가 아니다. 구현 우선순위와 플레이 테스트의 기준을 정하며, 세부 경제·
메타 해금 곡선은 별도 경제/메타 GDD에서 확정한다.

## 2. 비전 결정 반영

| 비전 결정 | 이 GDD의 적용 |
|---|---|
| 미로 빌딩을 핵심 재미로 승인 | 벽 한 칸으로 이동 경로와 타워 노출 시간을 만드는 선택을 중심 규칙으로 둔다. |
| 라이트 플레이어 중심 | 튜토리얼은 반드시 `벽 → 타워 → 조합` 순서로 진행한다. 한 번에 하나의 위협 개념만 소개한다. |
| 한 판 약 20분 | 레벨당 6~8개 웨이브를 목표 범위로 사용한다. 평균 시간은 검증 목표이며 확정값이 아니다. |
| 영구 성장 | 판 종료 시 메타 진전을 보여주고 저장 대상만 정의한다. 해금 조건·곡선·수치는 별도 경제/메타 GDD로 보류한다. |
| 웨이브 중 편집은 핵심 조작 | 이동 중에도 벽 추가·제거와 경로 재지정이 가능하며, 미리보기·확인·취소로 오입력을 줄인다. |

## 3. 핵심 가치와 대상 플레이어

- 대상 플레이어: 타워 디펜스 경험이 없거나 적은 라이트 플레이어.
- 첫 1분 목표: 벽이 적의 경로를 바꾸는 것을 직접 보고, 첫 타워를 경로 옆에 배치한다.
- 한 판 목표: 6~8개 웨이브의 위협을 읽고 생명을 남긴 채 마지막 적을 막는다.
- 반복 목표: 같은 맵에서 더 나은 미로, 적은 골드 사용, 다른 타워 조합을 시도한다.
- 핵심 감정: “한 칸과 한 코인의 교환”이 즉시 결과로 보이는 통제감.

### 핵심 가치

| 가치 | 플레이 행동으로의 변환 | 검증 질문 |
|---|---|---|
| 보이는 경로 설계 | 벽 배치 전후 경로와 사거리 교차를 비교한다. | 플레이어가 결과를 “경로가 길어짐”으로 설명하는가? |
| 조합의 이득 | 감속·직사·고화력·대공 역할을 구분해 배치한다. | 단일 타워로 모든 위협을 처리하려는가, 역할 조합을 만드는가? |
| 비용 있는 즉시 판단 | 미리보기에서 비용과 결과를 확인한 뒤 확정한다. | 오입력 전에 취소하거나 거부할 수 있는가? |
| 위협 예측과 변형 | 다음 웨이브 정보를 보고 자원을 배분한다. | 같은 웨이브에서 대응 타워 선택이 실제로 달라지는가? |
| 짧고 완결된 학습 | 실패 후 다음 판에서 고칠 위치·조합·자원 선택을 읽는다. | 두 번째 판에 관찰 가능한 전략 변화가 생기는가? |

## 4. 플레이어 목표와 성공/실패 조건

### 플레이어 목표

1. 입구에서 출구까지 항상 통행 가능한 경로를 유지한다.
2. 제한된 골드로 벽과 타워를 배치해 적에게 더 긴 공격 노출 시간을 제공한다.
3. 지상/공중, 빠른/느린, 일반/고체력 위협에 맞는 타워 역할을 조합한다.
4. 웨이브가 진행되는 동안 취약 구간을 관찰하고 필요한 경로 한 칸을 즉시 수정한다.
5. 레벨의 마지막 웨이브와 남은 적이 모두 처리될 때까지 생명을 보존한다.

### 성공 조건

- 마지막 웨이브의 스폰이 끝나고, 살아 있는 적이 0이며, 생명이 1 이상이다.
- 성공 판정은 스폰 완료와 적 소멸을 함께 확인한다. 스폰만 끝난 시점에서는 성공하지 않는다.
- 결과 화면은 성공 이유, 남은 생명, 사용 자원, 주요 타워 기여, 다음판에 바꿀 한 가지를 보여준다.

### 실패 조건

- 적이 출구에 도달해 생명이 0이 되면 즉시 레벨 실패다.
- 실패는 입력 오류가 아니라 배치·조합·자원 결정으로 원인을 설명할 수 있어야 한다.
- 결과 화면은 최소한 “어떤 위협이 누출됐는지”와 “공격·감속·대공 중 부족한 역할이 무엇인지”를 제공한다.

### 빌드 조건

| 입력 | 허용 조건 | 거부 또는 취소 |
|---|---|---|
| 벽/타워 추가 | 빈 셀, 충분한 골드, 입구→출구 통행 경로가 남음 | 비용 부족, 점유 셀, 입구/출구, 완전 차단 |
| 벽 제거 | 제거된 뒤 경로가 유효함 | 대상 없음 또는 현재 편집 확인 단계에서 취소됨 |
| 타워 제거/판매 | 선택 가능한 타워, 표시된 환급액 | 미확정 UX나 선택 불명확 시 실행하지 않음 |
| 웨이브 중 편집 | 유효한 편집과 최종 확인이 완료됨 | 미리보기가 불확실하거나 확인이 취소됨 |

## 5. 핵심 루프

```text
다음 위협 확인
→ 벽 또는 타워 역할 선택
→ 후보 셀의 경로·사거리·비용 미리보기
→ 확인 후 배치 또는 편집
→ 경로와 적 이동 변화 관찰
→ 처치 보상 획득
→ 남길 골드와 다음 위협 대응 결정
```

### 30초 결정 루프

플레이어는 이 칸을 벽으로 만들어 공격 시간을 살지, 타워로 만들어 직접 화력을 살지,
아니면 다음 위협까지 골드를 남길지 판단한다. 배치 직후 경로 변화와 비용 결과가 한 화면에 보여야 한다.

### 웨이브 루프

웨이브 시작 전에 다음 위협을 읽고 준비한다. 진행 중에는 누출 위험 구간을 관찰한 뒤 벽 추가·제거로
경로를 즉시 수정한다. 처치 보상과 누출 결과를 다음 웨이브의 자원 선택에 반영한다.

### 레벨 루프

초반 골격 미로를 만든 뒤, 단순 위협을 견디면서 타워 역할을 추가한다. 중반에는 자원 저장과 전문 대응의
선택이 생기고, 마지막에는 지상/공중 또는 속도/체력 조합을 대비한다.

## 6. 핵심 메커닉

### 6.1 미로 빌딩

#### 목적

벽은 적을 막는 체력형 장벽이 아니라, 적이 타워 사거리 안에 머무는 시간을 구매하는 건설물이다.

#### 규칙

1. 벽은 빈 셀에만 배치하며, 타워와 입구·출구도 건설 공간과 별도로 취급한다.
2. 배치 후보를 적용한 상태에서도 입구에서 출구까지 통행 가능한 경로가 최소 하나 있어야 한다.
3. 경로 계산은 그리드 상의 최단 경로를 사용한다. 대각선은 기본 경로로 사용하지 않는다.
4. 완전 차단 배치와 이미 점유된 셀 배치는 자원을 차감하지 않고 거부한다.
5. 배치 전에는 기존 경로, 후보 경로, 증가/감소한 경로 길이를 겹쳐 보여준다.
6. 경로가 길어져도 타워 사거리에 더 오래 노출되지 않으면 투자가 유효하지 않을 수 있다.

#### 경로 편집의 피드백

- 후보 단계: 새 경로를 점선 또는 대비되는 색으로 표시
- 확인 단계: 비용, 예상 경로 길이, 주요 타워 사거리와의 교차 변화 표시
- 완료 단계: 적과 새 경로의 연결이 즉시 갱신되고, 취소/되돌리기 조건이 표시
- 거부 단계: “완전 차단”, “비용 부족”, “사용 중인 셀” 중 원인을 짧게 표시

#### 설계 경계

경로 길이 자체를 직접 보상하지 않는다. 벽만 무한히 늘리는 이익보다, 그 길이를 타워 사거리와
위협 대응에 연결하는 이익이 우선이다.

### 6.2 타워 역할과 조합

현재 프로토타입에는 Gun, Slow, Rocket, Anti-Air 역할이 있다. 아래 명칭과 효과는 기획적 역할을
설명하기 위한 것이며, 최종 역할명·수치·업그레이드 단계는 아직 확정하지 않는다.

| 역할 | 기획 목적 | 대응 위협 | 약점/트레이드오프 |
|---|---|---|---|
| 일반 화력 | 안정적인 단일 대상 지속 화력 | 일반 지상 적 | 전문 고체력·고속 상황에서 단독 효율 부족 |
| 감속/제어 | 적의 체류 시간을 늘려 다른 타워의 기회를 만듦 | 빠른 지상 적, 호위가 필요한 구간 | 단독 처치력이 낮아 화력 조합 필요 |
| 고화력 | 큰 피해를 느리게 전달 | 고체력 지상 적 | 발사 간격과 단일 상황 대응이 불리할 수 있음 |
| 대공 | 공중 목표 전담 대응 | 공중 적 | 지상 적에 기여하지 않아 배치 시점 중요 |

#### 조합 원칙

- 지상 대응과 공중 대응은 분리된 역할군으로 간주하며, 한 타워가 보편적으로 모두 해결하지 않는다.
- 고속 대응은 감속 하나가 아니라 “감속으로 시간을 늘리고 화력으로 처치”하는 조합으로 평가한다.
- 고체력 대응은 단일 고화력 또는 여러 번의 안정적 공격 중 실제 비용 효율과 위치 조건이 갈리도록 한다.
- 최소 경쟁 조합 예시(가설): 일반+감속, 고화력+감속, 일반+대공, 일반+고화력+대공.
- 조합 이득은 숨은 보너스보다 경로 노출 시간, 타겟 제한, 사거리 중첩이 만드는 관찰 가능한 이득이다.

### 6.3 웨이브 중 실시간 경로 편집

#### 핵심 조작 흐름

```text
이동 중인 적/취약 구간 확인
→ 편집 후보 셀 선택
→ 새 경로와 비용 미리보기
→ 확정 또는 취소
→ 이동 중인 지상 적을 새 경로에 재연결
→ 적 흐름과 남은 비용 즉시 표시
```

#### 합류 규칙

1. 공중 적은 지상 벽의 영향을 받지 않으며 기존 공중 이동 규칙을 유지한다.
2. 지상 적은 편집 확정 뒤에도 좌표가 바뀌지 않는다. 적은 현재 좌표에서
   새 경로의 다음 유효 구간으로 통행 가능한 연결을 이어 이동한다.
3. 새 경로는 적마다 계산하는 것이 아니라 맵 편집당 한 번 결정한다. 같은
   새 경로를 여러 적에게 공유하되, 각 적은 자신의 현재 좌표와 진행 위치에
   맞는 합류 지점을 따로 결정한다.
4. 적의 진행도는 편집 후 출구 방향으로만 증가하며 감소하지 않는다. 다음
   구간 선택은 같은 새 경로를 사용하는 같은 상태의 적에 대해 항상 같다.
5. 합류 구간은 지상 적이 통행 가능한 셀만 통과해야 한다. 출구 방향의 경로
   구간을 건너뛰는 단축, 입구 방향 역행, 좌표 보정으로 인한 순간 이동은
   허용하지 않는다.
6. 현재 좌표 또는 현재 이동 구간에서 유효한 다음 구간을 찾을 수 없는 편집은
   확정하지 않는다. 일부 적만 합류한 뒤 나머지 적이 실패하는 부분 적용도
   허용하지 않는다.

#### 점유 셀과 편집 경계

적 점유는 적이 현재 중심으로 위치한 셀뿐 아니라 다음 웨이포인트로 이동하는
현재 구간이 통과하는 셀까지 포함한다. `적 점유 셀` 표시는 플레이어가 편집
결과를 이해할 수 있도록 후보 단계에서 함께 보여준다.

| 편집 상황 | 허용/거절 | 확정 후 동작 |
|---|---|---|
| 빈 셀에 벽을 추가하고 새 경로가 존재하며 모든 지상 적에 안전한 합류가 있음 | 허용 | 맵, 경로, 모든 적의 합류 상태를 한 번에 갱신 |
| 적이 위치하거나 현재 통과 중인 셀에 벽을 추가 | 거절 | 비용과 맵, 경로, 적 좌표를 모두 유지하고 “사용 중인 셀” 표시 |
| 같은 셀을 여러 적이 사용하거나 합류점으로 공유 | 허용 후보 | 모든 적의 합류 가능성을 확인해 하나라도 실패하면 전체 거절 |
| 벽 제거로 더 짧은 경로가 생기며 출구 이전 구간을 건너뛸 위험이 있음 | 조건부 허용 | 적 좌표는 유지하고 현재 구간을 마친 뒤 새 경로의 다음 순방향 지점으로 연결 |
| 후보 적용 뒤 입구→출구 경로가 없음 | 거절 | 비용과 맵을 갱신하지 않고 “완전 차단” 표시 |
| 후보 경로는 있으나 적 하나의 합류 지점을 찾을 수 없음 | 거절 | 비용과 맵을 갱신하지 않고 “안전한 합류 없음” 표시 |

#### 편집 원자성

- 후보 단계에서는 임시 격자에서만 경로와 합류 가능성을 계산한다. 이 단계에서는
  실제 맵, 골드, 적 좌표, 진행도, 웨이포인트를 변경하지 않는다.
- 확정 단계는 `(편집 성공 + 경로 확정 + 모든 관련 적의 합류 확정)`을 하나의
  성공 결과로 간주한다. 세 조건 중 하나라도 실패하면 편집 전체를 거절한다.
- 비용 차감은 원자적 확정이 성공한 뒤에 수행한다. 이미 비용을 차감한 상태에서
  경로 계산이나 합류가 실패하면 되돌린다는 방식은 사용하지 않는다.
- 후보를 취소하거나 거절한 경우 모든 적은 기존 위치, 기존 경로, 기존 진행도를
  그대로 유지한다.

#### 모바일 오입력 방지

- 첫 탭은 선택과 미리보기, 두 번째 명시적 확인 탭으로 편집을 확정하는 방식을 기본 UX 가설로 둔다.
- 후보 유지 중에는 기존 경로와 새 경로를 동시에 표시한다.
- 후보 셀, 적 점유 표시, 합류 불가 원인, 확인 취소 위치를 동시에 확인할 수 있어야 한다.
- 비용이 발생하기 전까지 취소할 수 있고, 취소 시 적 경로는 변하지 않는다.
- 홀드, 드래그, 작은 셀 정밀 타격은 핵심 확인 과정의 필수 조건이 되지 않게 한다.
- 확인 방식은 UX 플레이 테스트 전까지 미정이다.

#### 확인 가능한 경계 사례

| ID | 준비 상태 | 편집 입력 | 통과 기준 |
|---|---|---|---|
| RT-01 | 지상 적이 후보 셀이 아닌 구간에 있음 | 빈 셀에 벽 추가 | 새 경로가 유효하고 적 좌표는 즉시 변하지 않으며 다음 이동이 순방향임 |
| RT-02 | 지상 적이 후보 셀 위 또는 통과 구간에 있음 | 같은 셀에 벽 추가 | 편집 거절, 비용·경로·좌표·진행도 불변, “사용 중인 셀” 표시 |
| RT-03 | 여러 지상 적이 서로 다른 진행 위치에서 같은 경로를 사용 | 합류점에 영향을 주는 편집 | 모든 적이 같은 경로 계산을 공유하지만 각자 안전한 다음 구간을 결정하고 역행·순간 이동 없음 |
| RT-04 | 한 적은 합류 가능, 다른 한 적은 합류 불가 | 복수 적에 영향을 주는 편집 | 한 적도 갱신하지 않는 전체 거절과 비용 불변 |
| RT-05 | 기존 경로에서 벽 제거 후보가 더 짧은 경로를 만듦 | 확인 편집 | 현재 구간을 끝내기 전 출구로 건너뛰지 않으며 진행도가 유지 또는 증가 |
| RT-06 | 공중 적과 지상 적이 동시에 이동 중 | 지상 셀 편집 | 공중 적의 경로와 좌표는 변하지 않고 지상 적만 합류 규칙을 적용 |
| RT-07 | 같은 맵·같은 편집 시점·같은 적 상태 | 동일 편집 반복 시뮬레이션 | 후보/확정 결과, 합류 지점, 좌표 변화, 잔여 진행 상태가 결정적으로 동일 |
| RT-08 | 후보 경로 계산 또는 합류 계산이 실패함 | 편집 확정 시도 | 실제 맵·비용·적 상태는 불변이며 거절 원인만 표시 |

## 7. 웨이브와 위협

### 7.1 웨이브 범위

- 레벨당 **6~8개** 웨이브.
- 개별 웨이브 목표 시간과 적 수는 가설이며, 한 레벨 평균 약 20분을 향한 검증 대상이다.
- 10웨이브 고정 프로토타입 데이터는 첫 GDD의 콘텐츠 사양이 아니며 6~8개로 재구성하는 갭이다.

### 7.2 위협 역할

| 위협 | 정의 | 요구하는 대응 | 소개 시점 가설 |
|---|---|---|---|
| 일반 지상 | 기준 속도와 체력의 기본 적 | 경로 설계 + 기본 화력 | 레벨 1 초반 |
| 고속 지상 | 체류 시간이 짧은 지상 적 | 감속 또는 집중 화력 | 레벨 1 후반 |
| 고체력 지상 | 오래 버티는 지상 적 | 고화력 또는 충분한 중첩 | 레벨 2 |
| 공중 | 벽 경로를 따르지 않는 적 | 공중 대응 타워 | 레벨 2~3 |
| 혼합 | 최소 두 위협이 같은 웨이브에 등장 | 역할 분산과 자원 배분 | 레벨 3 |
| 보스형 | 매우 높은 체력의 단일 위협 | 사전 준비와 여러 역할 | 레벨 3 마지막 후보, 수치 미정 |

### 7.3 웨이브 예시 구조

아래는 위협 학습 순서를 보여주는 **가설 예시**다. 적 수, 간격, 보상, 난이도 수치는 확정값이 아니다.

| 웨이브 위치 | 구성 목적 | 주요 위협 |
|---|---|---|
| 1 | 벽의 경로 효과 확인 | 일반 지상 단일 |
| 2 | 기본 타워의 처치 확인 | 일반 지상 증가 |
| 3 | 조합 도입 | 고속 지상 + 일반 화력 |
| 4 | 전문 대응 학습 | 고체력 또는 공중 하나 |
| 5~6 | 대응 선택 교차 | 앞선 두 위협의 혼합 |
| 7 | 자원 분배 시험 | 혼합 + 밀도 증가 |
| 8 | 레벨 완결/종합 시험 | 보스형 후보 또는 복합 위협 |

웨이브 시작 전에 적 종류, 주요 수량대, 특성 아이콘, 출현 순서의 요약을 보여준다.
무작위 구성은 첫 프로토타입 범위 밖이며 같은 입력이 같은 결과를 만들도록 한다.

## 8. 타워와 경제 규칙

### 골드

- 골드는 건설·업그레이드·판매 결과·처치 보상에서 사용한다.
- 시작 자원과 처치 보상은 레벨이 아니라, 다음 판단을 가능하게 하는 예산으로 설계한다.
- 모든 지출은 미리보기에서 표시하며, 취소된 배치는 자원을 소비하지 않는다.
- “저축”도 유효한 선택이어야 한다. 현재 사용할 자원이 미래 전문 위협 대응을 막지 않아야 한다.
- 골드는 편집 성공 후에만 차감하거나 지급한다. 후보 계산, 취소, 거절, 입력
  실패가 골드와 누적 집계를 바꾸면 안 된다.

### 비용 원칙

| 항목 | 기획 원칙 | 수치 상태 |
|---|---|---|
| 벽 | 경로 시간 1단위를 구매하는 저비용 투자 | 프로토타입 값 존재, 밸런스 미검증 |
| 타워 | 역할을 추가하는 중간 투자 | 프로토타입 값 존재, 상대 효율 미검증 |
| 업그레이드 | 같은 위치의 역할을 강화하거나 좁은 사거리를 보완하는 선택 | 모듈 계산 존재, 플레이 UX 미연결 |
| 판매 | 잘못된 역할/위치의 회수와 재배치를 돕되, 무제한 무료 재설계를 허용하지 않음 | 현재 반환률 예시 존재, 확정 아님 |
| 처치 보상 | 위협 해결 후 다음 판단을 열어주는 수입 | 적 정의 값 존재, 경제 곡선 미검증 |

### 편집·판매의 공통 원칙

#### 원자적 거래

1. 후보 단계는 임시 상태에서 `(맵 유효성 + 경로 + 모든 지상 적의 합류 +
   비용 + 환급액)`을 함께 계산한다.
2. 확정 조건이 모두 통과한 뒤 한 번에 실제 맵, 타워 목록, 적 합류 상태, 골드를
   갱신한다. 중간 단계가 실패하면 전체를 거절하고 후보 이전 상태를 유지한다.
3. 판매·제거의 환급은 비용과 같은 확정 묶음으로 처리한다. 성공 전에 골드를
   지급하거나, 객체를 제거한 뒤 경로 실패를 돌려받는 구현은 허용하지 않는다.
4. 취소, 비용 부족, 대상 없음, 경로 없음, 안전한 합류 없음은 모두 골드와
   누적 지출 기록을 바꾸지 않는다.

#### 벽의 추가와 제거

- 빈 셀에 벽 추가는 표시된 비용을 한 번 지불하고, `6.3`의 점유·경로·합류
  조건을 모두 통과했을 때만 확정한다.
- 기존 벽 제거는 새 지상 경로와 모든 지상 적의 안전한 합류를 먼저 검증한다.
  실패하면 벽을 유지하고 골드도 지급하지 않는다.
- 제거 성공 시 최초 설치비보다 적은 환급을 지급하는 손실률 정책을 기본 방향으로
  둔다. 반복 추가/제거는 각 완결 거래마다 손실이 누적되어 자원을 늘릴 수 없다.
- 환급은 같은 벽을 다시 설치할 때 새 설치 거래로 계산한다. 이전 환급액이 다음
  설치의 할인이나 무료 설치 근거로 쓰이면 안 된다.

#### 타워 판매와 업그레이드

- 환급 기준은 타워 최초 설치비와 실제로 지불한 업그레이드 비용의 합계인
  `총 투자액`이다. 현재 위력, 남은 발사 횟수, 상대적 성능은 환급 계산에 사용하지
  않는다.
- 판매 전 미리보기는 대상 역할, 총 투자액, 예상 환급액, 환급 후 골드, 제거 뒤
  예상 경로 변화를 함께 표시한다.
- 첫 선택에서 판매 후보만 만들고, 명시적 확정에서만 제거와 환급을 실행한다.
  취소·대상 변경·확정 실패는 현재 타워와 골드를 그대로 유지한다.
- 타워가 경로 셀을 막고 있으면 판매 후보는 해당 위치의 새 경로와 모든 지상
  적의 합류 가능성도 검증한다. 판매 성공은 타워 공격 목록과 맵 점유 상태까지
  같은 원자적 거래에 포함한다.
- 업그레이드는 후속 구현에서 별도 확인 입력을 사용하며, 실패 시 현재
  레벨·능력치·골드를 유지한다. 판매 환급은 성공한 업그레이드만 총 투자액에
  포함한다.

#### 반복 편집 악용 방지

| 후보 정책 | 장점 | 위험 | 이번 판정 |
|---|---|---|---|
| 환급 손실률 | 같은 위치의 반복 편집마다 비용이 자연스럽게 누적되고 조작이 단순함 | 손실이 너무 크면 오배치 회복이 어렵고, 너무 작으면 반복 최적화 억제가 약함 | 기본 검증 후보 |
| 거래별 쿨다운 | 짧은 시간의 반복 건설/제거 자동 최적화를 직접 제한함 | 플레이 속도와 입력 시점에 인위적 제약을 만들고 타이밍 실력만 시험할 수 있음 | 기본 정책에서는 제외 |
| 최소 유지 비용/이용료 | 편집 빈도와 유지 시간에 비용 압력을 직접 부여함 | 장기 보유와 실시간 조작을 추가 회계 시스템으로 복잡하게 만듦 | 후속 밸런스 후보 |
| 환급 0% | 반복 편집 이득을 확실히 차단함 | 초보자의 시행착오와 오배치 회복을 사실상 막음 | 부적합 |
| 전액 환급 | 재배치와 탐색을 가장 허용함 | 합법적인 골드 증가 또는 반복 자동 최적화를 통제하기 어려움 | 부적합 |

검증할 기본 관계는 `0 < 환급 < 설치/업그레이드 투자액`이다. 같은 벽 또는
타워를 추가/제거/판매한 뒤 다시 같은 비용으로 설치하면 골드는 반드시 감소해야
한다. 최종 손실률과 별도 쿨다운 도입 여부는 플레이 테스트로 다음 항목을 비교한
뒤 결정한다.

- 초보자가 첫 오배치를 회복한 뒤 같은 웨이브에서 의미 있는 선택을 이어가는가?
- 반복 편집으로 같은 결과를 얻는 총 투자액이 정상 설계 대비 불리한가?
- 웨이브 중 조작이 별도의 금기 지식 없이 미리보기와 환급액만으로 이해되는가?
- 판매로 타워 조합을 극단적으로 교체하는 횟수와 남은 골드가 다음 위협 선택을
  유지하는가?

#### 웨이브 상태 경계

| 상태 | 벽 추가 | 벽 제거 | 타워 판매 | 허용 조건과 피드백 |
|---|---|---|---|---|
| 빌드 | 허용 | 허용 | 허용 | 후보 경로·환급액을 확인하고 확정 |
| 웨이브 중 | 허용 | 허용 | 허용 | `6.3`의 점유 셀·경로·모든 적 합류 검증을 같은 확정에 포함 |
| 게임 오버/승리 | 거절 | 거절 | 거절 | 결과 화면 밖의 맵·골드 상태는 변경하지 않음 |
| 후보 미리보기 | 확정 전 | 확정 전 | 확정 전 | 실 상태와 골드는 불변이며 취소 가능 |

웨이브 중 판매와 편집은 기능적으로 허용하되, 긴 확인 동작이나 정확한 드래그를
필수 조건으로 사용하지 않는다. 다음 웨이브 시작 같은 별도 상태 전환은 편집
확정과 같은 프레임에 처리하지 않는다.

| ID | 준비 상태 | 입력 | 통과 기준 |
|---|---|---|---|
| EC-01 | 유효한 빈 셀과 충분한 골드 | 벽 후보 선택 뒤 취소 | 골드, 누적 지출, 맵, 경로, 적 상태 불변 |
| EC-02 | 벽 추가 거래가 확정됨 | 같은 벽 제거 성공 | 환급은 설치 투자보다 작고 골드·맵·경로가 한 번에 갱신됨 |
| EC-03 | 설치 가능한 같은 조건 | 같은 벽의 추가/제거를 반복 | 한 주기를 반복해도 골드가 원래 값보다 증가하지 않고 누적 손실이 발생함 |
| EC-04 | 이동 중인 지상 적이 새 경로의 한 합류에 실패함 | 벽 제거 또는 타워 판매 확정 | 맵, 골드, 타워, 경로, 모든 적 상태가 확정 전과 같음 |
| EC-05 | 총 투자액이 있는 타워 선택 | 판매 미리보기 뒤 취소 | 타워, 타워 목록, 골드, 공격 대상, 맵 점유 불변 |
| EC-06 | 업그레이드 성공 기록이 있는 타워 | 타워 판매 성공 | 성공한 설치·업그레이드 비용만 총 투자액에 포함되고 손실률 적용 후 환급 |
| EC-07 | 선택한 벽이나 타워 후보가 확정 전에 사라짐 | 같은 대상에 중복 제거 또는 판매 확정 | 중복 환급하지 않고 현재 맵·대상·골드·누적 기록 유지, 실패 원인 표시 |
| EC-08 | 결과 화면 상태 | 편집 또는 판매 입력 | 골드와 맵, 타워, 적, 결과 상태 모두 불변 |

현재 `economy` 모듈은 지출·보상·생명만 관리하고, 타워 모듈에는 전체 투자액의
60%를 돌려주는 예시 판매 계산이 있다. 이 값은 사용자 UX와 맵·적 원자성에
아직 연결되지 않은 구현 사실일 뿐 최종 정책값이 아니다.

## 9. 튜토리얼 순서

튜토리얼은 반드시 **벽 → 타워 → 조합** 순서이며, 설명보다 플레이어의 직접 결과를 먼저 보여준다.

### 1단계: 벽

- 목표: 벽 한 칸을 놓아 경로가 우회하는 것을 확인한다.
- 제한: 첫 시도에는 타워 선택과 경제 세부를 숨긴다.
- 성공 신호: 적이 새 경로로 이동하고 플레이어가 경로 변화를 설명한다.
- 금지: 완전 차단 위치는 미리 거부하고 원인을 보여준다.

### 2단계: 타워

- 목표: 길어진 경로 옆에 기본 타워를 배치해 공격 기회가 늘어나는 것을 본다.
- 제한: 첫 타워는 지상 일반 적만 대상으로 하고 공중·감속은 설명하지 않는다.
- 성공 신호: 플레이어가 사거리 교차 구간에 타워를 두는 이유를 설명한다.

### 3단계: 조합

- 목표: 고속 또는 고체력 위협 하나를 도입하고 두 역할의 조합 효과를 확인한다.
- 제한: 한 웨이브에는 공중과 고체력을 동시에 도입하지 않는다.
- 성공 신호: “기본 타워만으로는 부족해 전문 역할을 추가했다”는 행동이 관찰된다.
- 실시간 편집: 조합 이해 후 짧은 위기에서 후보 미리보기→확정 순서를 한 번 안내한다.

## 10. 레벨 1~3 난이도 가설

수치가 아니라 학습 질문과 위협 단계만 정의한다. 모든 레벨은 6~8개 웨이브다.

| 레벨 | 학습 질문 | 단순 위협 진행 | 자원/공간 압력 | 성공 가설 |
|---|---|---|---|---|
| 1 | 벽이 왜 타워의 기회를 만드는가? | 일반 → 일반 수량 증가 → 빠른 지상 | 여유를 두고 첫 선택을 실패해도 회복 가능 | 초보자가 벽·기본 타워·한 가지 조합을 한 판에 완수 |
| 2 | 어느 위협에 전용 역할이 필요한가? | 일반 → 고체력 **또는** 공중 → 두 위협 교차 | 첫 레벨보다 선택 비용과 위치 압력 증가 | 고체력/공중 대응 타워를 선택하지 않으면 특정 웨이브에서 명확히 손해 |
| 3 | 어떻게 자원을 나누고 실시간 경로를 바꾸는가? | 속도/체력/공중을 순차 혼합 | 실시간 편집을 늦추면 누출, 과다 편집하면 자원 손실 | 미리 준비한 골격과 한두 번의 실시간 수정이 함께 필요 |

### 조정 금지 사항

- 난이도를 체력이나 수량만 늘려 해결하지 않는다.
- 레벨 1에서 공중·고체력·고속을 동시에 소개하지 않는다.
- 레벨 2에 보스형 적을 추가하지 않는다.
- 레벨 3도 8개를 넘지 않는다.

## 11. 영구 성장 메타 개요

### 판 종료 후 기록

- 해금된 타워 또는 업그레이드
- 기지/진행 상태
- 선택적으로 남은 생명, 사용 골드, 각 레벨 최고 성적
- 결과 화면은 점수보다 “다음 판에 무엇이 달라지는가”를 먼저 보여준다.

### GDD 경계

- 한 판 안에서는 처치와 배치 경제만으로 승리 가능해야 한다. 메타가 자동 승리를 보장하지 않는다.
- 해금은 새로운 역할·기회비용을 열 수 있으나 기존 타워의 단순 상위 수치만 반복하지 않는다.
- 저장 형식, 해금 순서, 해금 빈도, 영구 수치 보너스, 반복 보상량은 **별도 경제/메타 GDD에서 미결정**이다.
- 수익화, 랭킹, 계정, 클라우드 저장은 이 문서의 전제가 아니다.

## 12. 테스트 가능한 가설

모든 수치 임계값은 검증 전 예시이며, 지표와 실패 방식이 먼저 중요하다.

| 가설 | 확인 지표 | 검증 방법 | 통과 방향(예시) |
|---|---|---|---|
| 벽 투자가 타워 기회를 만든다. | 추가 경로 길이, 타워 노출 시간, 총 타격량, 생존 생명 | 같은 맵·적·타워에서 벽 유무를 결정적 시뮬레이션 | 경로만 늘린 전략보다 사거리와 겹친 미로가 일관되게 효율적 |
| 하나의 만능 조합이 없다. | 조합별 승률, 사용 골드, 누수 위협 | 위협 구성이 다른 6~8웨이브 배치 시뮬레이션 | 최소 3개 유효 조합이 서로 다른 약점에서 경쟁 |
| 다음 위협 정보가 선택을 개선한다. | 준비 선택 시간, 첫 대응 종류, 웨이브 전후 배치 변경 | 예고 정보 유무 비교 플레이 테스트 | 예고가 있을 때 대응과 설명이 더 명확하고 오배치 감소 |
| 실시간 편집이 관전 시간을 줄인다. | 편집 횟수, 편집 시점, 대기 시간, 오입력/취소율 | 입력 이벤트와 웨이브 타임라인 기록 | 준비 배치가 과반을 유지하면서 위기 때 의미 있는 편집 발생 |
| 재경로 지정이 결정적이다. | 동일 시드의 위치, 체류 시간, 결과 | 이동 중 편집 통합 하네스 | 동일 입력에서 동일 경로·위치·결과, 역행/순간이동 없음 |
| 튜토리얼이 한 개념씩 전한다. | 이해 설명, 잘못 배치 수, 완료 시간 | 신규 이용자 1~2회 관찰 | 첫 판 1분 안에 벽과 타워 차이를 실행·설명 |
| 라이트 플레이어 수준 난이도다. | 승률, 실패 원인 인지, 반복 선택 변화 | 레벨 1~3 초보 플레이 테스트 | 레벨 1은 학습 완료, 2는 전문 대응, 3은 조합/실시간 판단으로 실패 |

## 13. UX와 피드백 요구

- 상시 정보: 골드, 생명, 현재 웨이브, 현재 건설/편집 선택.
- 필요 시 확장: 다음 위협, 타워 역할, 비용·환급, 선택 이유, 상세 수치.
- 모든 기본 행동은 세로 화면의 엄지 영역에서 탭 → 미리보기 → 확인으로 연결한다.
- 색만으로 지상/공중/타워 역할을 구분하지 않고 형태, 아이콘, 짧은 라벨을 함께 쓴다.
- 실패 입력에는 비용 변화를 일으키기 전에 원인을 표시한다.
- 성공/실패 결과는 다음 판의 수정 가능한 판단 하나를 반드시 보여준다.

## 14. 현재 프로토타입과의 갭

| 영역 | 현재 구현 사실 | GDD 갭/필요 작업 |
|---|---|---|
| 맵/경로 | 오픈 그리드, 벽/타워 배치, BFS, 완전 차단 방지, 현재 경로 표시 | 배치 전 후보 경로·경로 길이·사거리 교차 미리보기 부족 |
| 실시간 편집 | 배치 후 경로를 다시 계산하고 기존 적에 새 경로를 전달하는 흐름 존재 | 확인 UX, 안전한 합류 규칙, 역행/순간이동 통합 검증 부재 |
| 타워 | Gun/Slow/Rocket/Anti-Air와 업그레이드/판매 계산 존재 | 역할 설명, 조합 피드백, 강화·판매 입력 미연결 |
| 적 | Normal/Fast/Tank/Flyer/Boss 역할 존재 | 레벨별 학습 순서와 역할별 밸런스 미검증 |
| 웨이브 | 10개 공통 웨이브 데이터, 수동 시작 | 6~8개/레벨 범위, 다음 위협 정보, 레벨별 콘텐츠 미구현 |
| 경제 | 시작 골드, 지출, 처치 보상, 생명 관리 | 경로 투자 대비 효율, 저장 이유, 판매 UX, 레벨 경제 곡선 미검증 |
| 승패 | 생명 0은 패배, 모든 웨이브·적 완료는 승리 | 결과 원인, 타워 기여, 개선 조언, 메타 진전 결과 부재 |
| 튜토리얼 | 튜토리얼 전용 단계 없음 | `벽 → 타워 → 조합` 온보딩 필요 |
| 화면 | 9×14형 맵과 하단 HUD 구조 | 세로 화면에서 전체 경로와 터치 정확도의 통합 검증 필요 |
| 메타 | 메타 저장과 해금 없음 | 저장 구조·결과 화면·영구 성장 GDD 필요 |
| 테스트 | 경로, 맵, 타워, 적, 웨이브, 경제 단위 하네스 존재 | 통합 시뮬레이션, 전략 다양성, 이동 중 편집, UX 검증 부족 |

## 15. 범위와 제외

### 포함

- 레벨 1~3의 6~8웨이브 학습 곡선
- 미로 빌딩, 역할 타워 조합, 웨이브 중 경로 편집
- 지상/공중, 속도/체력 위협
- 다음 위협 예고, 승리/실패 원인 피드백
- 골드 지출·처치 보상·업그레이드·판매의 기획 규칙
- 영구 성장 메타의 데이터와 결과 화면 개요

### 이번 문서에서 제외

- 최종 밸런스 수치와 경제 계수
- 메타 해금 순서, 속도, 저장/동기화 구현
- 수익화, 계정, 랭킹, 소셜 기능
- 아트·사운드·스토리 방향
- 고급 모드, 무한 웨이브, 영웅 조작, 자동 추천

## 16. 검증 계획

### 하네스 우선

1. 후보 배치 전후 경로 길이와 완전 차단 여부
2. 동일 시드에서 이동 중 재경로 결과의 결정성
3. 지상/공중, 고속/고체력 조합별 승률과 골드 효율
4. 웨이브 6~8개, 스폰 종료와 적 전멸이 함께 충족될 때만 성공 판정
5. 판매/업그레이드 비용과 취소 시 골드 불변
6. `EC-01`~`EC-08`의 반복 편집 손실, 실패 원자성, 웨이브 상태별 허용 경계

### 최소 런타임

하네스로 재현할 수 없는 입력 미리보기, 세로 화면 터치 정확도, HUD 가림,
적 흐름의 시각적 합류만 LÖVE2D 실행으로 확인한다.
