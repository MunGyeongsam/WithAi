## 2. 게임 한 줄 정의

> **모바일 세로 화면의 미로 빌딩 타워 디펜스에서, 플레이어가 벽으로 적의 이동 경로를 설계하고
> 타워 조합으로 서로 다른 위협을 막아내며 “한 칸과 한 코인의 교환”을 반복하는 전략 게임.**

- 장르: 미로 빌딩 타워 디펜스
- 현재 기술 기반: LÖVE 11.5 프로토타입, 세로 가상 해상도와 터치/마우스 입력
- 핵심 플레이 판타지: 적에게 장거리 이동을 강요하는 미로 설계자이자 제한 자원을 배분하는 방어 사령관
- 상태: **추천 방향안**. 모바일 출시 대상 범위는 확정되지 않았다.

## 3. 목표 플레이어

### 핵심 이용자 — 라이트 플레이어 (승인됨)

**정의**: 타워 디펜스를 처음 접하거나 익숙하지 않은 플레이어

- 한 번의 배치가 결과에 보이는 영향을 이해하고, 시행착오로 전략을 개선하는 플레이어
- 긴 설명보다 “경로가 바뀌고, 타워가 효율적으로 공격하는 것”을 직접 보고 배우는 이용자
- 짧은 시간에도 하나의 의미 있는 방어 판단을 완료하려는 이용자

**설계 기준**:
- 튜토리얼: "벽 하나" → "첫 타워 배치" → "조합 대응" 단계적 소개
- UX 정보: 필수 의사결정 항목(경로, 타워 효율)만 강조, 세부 수치는 옵션 정보로
- 난이도 곡선: 초반(레벨 1~3)은 단순 위협 하나씩, 중반(레벨 4~6)은 혼합 위협, 후반(레벨 7+)은 타워 조합 최적화

**이용자 세분화 (향후 고려사항)**: 
- 숙련 플레이어는 같은 레벨을 덜 사용해서 풀거나 무제한 모드로 진행 가능

### 예상 플레이 시간 — 약 20분 (승인됨)

- 한 번의 집중 판단: 약 30초
- 웨이브 단위: 약 3분
- 레벨 한 판: **약 20분** (목표값)
- 목표 웨이브: 약 6~8개 / 레벨

**검증 계획**: 평균 플레이 타임 측정으로 목표값 대비 편차 확인

### 기대하는 숙련도

- **초반 (튜토리얼 완료까지)**: 타워 디펜스 기본 이해가 없어도 경로와 배치의 결과를 관찰하며 학습 가능
- **중반 (레벨 4~6)**: 지상/공중, 속도/체력, 사거리/화력 같은 위협 차이를 구분 대응
- **후반 (레벨 7+)**: 타워 종류와 미로 형태를 조합해 자원 효율을 설명할 수 있음
- **숙련자의 도전**: 같은 레벨을 더 적은 자원, 더 많은 생명 또는 다른 유효 전략으로 해결

## 4. 만들고 싶은 재미

### 반복해서 내리고 싶은 핵심 의사결정

1. 이 칸에 벽을 두어 경로를 얼마나 늘릴 것인가, 타워를 둘 것인가?
2. 지금 골드로 일반 대응력을 높일 것인가, 다음 위협을 위한 전용 대응을 준비할 것인가?
3. 체력·속도·공중 특성을 고려해 어느 타워 조합을 적용할 것인가?
4. 이미 만든 경로와 타워 배치를 유지할 것인가, 비용을 들여 재설계할 것인가?

핵심은 배치 자체보다 **배치 전후의 기회비용이 보이는 선택**이다.

### 실패와 성공의 주요 원인

| 구분 | 성공 원인 | 실패 원인 |
|---|---|---|
| 미로 | 경로 연장과 화력 사거리 노출 구간이 겹침 | 벽을 늘렸지만 타워가 활용하지 못하는 경로 |
| 조합 | 지상, 공중, 고체력, 고속 위협을 구분 대응 | 단일 타워나 단일 대응 속성에 과도하게 집중 |
| 경제 | 다음 웨이브 정보에 맞춰 여유 자원을 남김 | 초기 자원 낭비 또는 수익을 기대한 과도한 투자 |
| 대응 시점 | 위협 전에 개선하고 위기 중 우선순위를 정함 | 생명 감소를 보면서도 무엇을 바꿔야 할지 모름 |

실패는 무작위가 아니라 플레이어가 고칠 수 있는 배치·조합·자원 결정에서 발생해야 한다.

### “한 판 더”를 만드는 요소

- 같은 맵에서 다른 미로 형태로 공격 기회를 다시 설계할 수 있음
- 성공이 단순 승리 외에도 남은 생명, 사용 자원, 대체 전략 수로 비교됨
- 실패 직후 “어떤 칸과 어떤 타워가 문제였는지”를 설명 가능하게 제공함
- 다음 판에서 한 가지 판단을 바꾸면 결과가 달라지는 크기의 선택 단위

## 5. 핵심 가치 3~5개

우선순위가 높을수록 기능 추가·콘텐츠·UX 결정에서 앞선다.

### 1순위: 보이는 경로 설계

- 정의: 플레이어의 건설 선택이 적의 경로 길이, 공격 노출 시간, 위험 구간을 즉시 이해 가능하게 바꾼다.
- 적용 기준:
  - 배치 전후에 경로 변화를 비교할 수 있다.
  - 건설은 단순 체력 증가가 아니라 이동 시간이라는 방어 자원을 만든다.
  - 완전한 경로 차단은 우회 가능 경로 없이는 허용하지 않는다.
- 구현/기획 판단: 경로 피드백이나 배치 정확도를 희생하는 화려한 콘텐츠보다 경로의 원인과 결과를 우선한다.

### 2순위: 조합의 이득

- 정의: 서로 다른 타워와 적 특성을 조합할 때 각 요소를 따로 쓰는 것보다 전략적 이득이 생긴다.
- 적용 기준:
  - 최소 3개 이상의 유효한 타워 역할 조합이 경쟁한다.
  - “좋은 타워 하나”보다 배치 위치와 역할 조합이 설명 가능하게 중요하다.
  - 공중·고속·고체력 같은 위협이 특정 단일 조합의 보편적 승리를 막는다.
- 구현/기획 판단: 새 타워는 수치가 높은 버전이 아니라 기존 선택의 기회비용이나 역할 조합을 바꾸는 경우에만 추가한다.

### 3순위: 비용 있는 즉시 판단

- 정의: 플레이어의 작은 결정을 즉시 관찰할 수 있지만, 되돌릴 수 없는 비용 없이 작은 실수를 반복 학습하는 데 지장이 없어야 한다.
- 적용 기준:
  - 벽/타워 선택과 배치에서 결과와 비용이 한 화면에서 확인된다.
  - 판매·업그레이드 여부가 필요하다면 현재 가치와 기회비용이 사전에 보인다.
  - 잘못된 입력은 자원을 소비하기 전에 거부되거나 명확히 되돌릴 수 있다.
- 구현/기획 판단: 입력 속도보다 오배치 방지와 원인 피드백을 우선한다.

### 4순위: 위협의 예측과 변형

- 정의: 플레이어가 다음 위협을 읽고 준비할 수 있으며, 웨이브마다 같은 행동을 기계적으로 반복하지 않는다.
- 적용 기준:
  - 다음 웨이브에 필요한 대응 정보를 시작 전에 이해할 수 있다.
  - 적 특성은 새로운 역할을 만들고, 체력 증가만으로 난이도를 올리지 않는다.
  - 동일 레벨에서 대응 우선순위가 판 중 여러 번 바뀐다.
- 구현/기획 판단: 새 적은 “더 빨리 도착함”보다 기존 방어 전략을 어떻게 바꾸는지가 핵심이다.

### 5순위: 짧고 완결된 학습

- 정의: 한 판이 독립된 문제 해결의 시작·긴장·해답으로 구분되고, 다음 판에 적용 가능한 학습을 남긴다.
- 적용 기준:
  - 첫 판에서 기본 조작과 실패 원인을 습득한다.
  - 중간 이탈 가능성을 고려해 게임 상태와 중요한 숫자를 즉시 읽는다.
  - 한 판의 결과 화면은 성공/실패뿐 아니라 바꿀 선택을 보여준다.
- 구현/기획 판단: 영구 보상이나 장기 수집은 핵심 플레이 검증 전에 우선순위를 낮춘다.

## 6. 비목표

### 이번 프로젝트에서 만들지 않을 것

- 오픈월드, 스토리 중심 RPG, 실시간 PvP
- 타워를 직접 조종하는 액션 게임
- 방치형 수익 구조나 자동 전투가 핵심인 게임
- 시장성 또는 수익화를 전제로 한 콘텐츠·결제 설계
- 특정 화풍을 전제로 한 아트 제작

### 우선 구현하지 않을 것

- 계정, 랭킹, 클라우드 저장, 소셜 기능
- 가챠, 일일 보상, 시즌 패스, 영구 업그레이드
- 방대한 타워·적·스킨 카탈로그
- 스토리 캠페인, 컷신, 보스 연출
- 고급 사운드·파티클·연출 중심의 폴리싱

### 일반적인 타워 디펜스 기능 중 제외 후보

| 후보 | 제외/보류 이유 | 재검토 조건 |
|---|---|---|
| 플레이어가 영웅을 직접 이동·공격 | 미로 설계 의사결정을 희석할 수 있음 | 타워 조작 밖의 반복 재미가 확인되면 별도 프로토타입 |
| 무한 랜덤 타워 강화 | 조합 예측성과 학습 가능성을 낮춤 | 콘텐츠 반복 테스트에서 선택 고갈이 확인될 때 |
| 완전 자유 멀티 입구 | 한 손 UX와 경로 인지 부담이 큼 | 단일 입구·출구 밸런스가 확보되고 관찰 지표가 존재할 때 |
| 실시간 타워 유닛 수동 배치 이동 | 조작 복잡도 증가, 오입력 위험 | 포스트프로토타입 실험으로 재미가 입증될 때 |
| 자동 웨이브 최적화/추천 해답 | 플레이어의 전략 판단을 대체함 | 접근성 보조 옵션으로 범위를 제한할 때 |

## 7. 코어 루프

### 30초 루프: 한 번의 결정과 결과

```text
현재 경로와 다음 위협 확인
→ 벽 또는 타워 선택
→ 한 칸에 배치
→ 경로·사거리·비용 변화 확인
→ 유지 또는 다음 배치 결정
```

- 현재 구현: 빌드/웨이브 중 배치, 비용 차감, 경로 재계산은 존재한다.
- 제안: 배치 전 예상 경로 길이와 주요 사거리 교차를 명확히 피드백한다.
- 성공 관찰: 플레이어가 한 탭 후 경로와 다음 선택을 살펴보는 시간이 생긴다.

### 3분 루프: 한 웨이브 대응 (웨이브 중 경로 편집 포함)

```text
다음 웨이브 위협 확인
→ 골드를 배치·업그레이드·저축 중 선택
→ 웨이브 시작
→ 취약 지점 관찰
→ 적극적 실시간 경로 편집 (핵심 조작)
→ 처치 보상과 생명 결과 확인
→ 다음 위협에 반영
```

**웨이브 중 경로 편집 결정** (승인됨):
- **정의**: 웨이브 진행 중 경로를 즉시 편집하고 그 결과를 바로 본다는 행동 자체가 핵심 의사결정
- **설계**:
  - 웨이브 중 적이 이동 중이어도 새로운 경로를 추가·제거할 수 있다
  - 경로 변경 순간 적은 현재 위치에서 새로운 경로로 재경로지정
  - 모바일 입력 오류 방지를 위해 "확인 타월" 또는 취소 메커니즘 포함 (버튼 길게 누르기, 2단계 확인 등)
  - 경로 변경 전후의 적 흐름을 화면에 겹쳐 보여 오입력 예방
- **심리 피드백**: 
  - 위기 상황에서 "이 한 칸이 차이를 만든다"는 긴장감
  - 변경 직후 적이 다르게 움직이는 것을 즉시 확인 가능
- **제약**:
  - 경로 변경으로 인한 적 위치 버그 없음 (테스트 필수)
  - 한 손 UX를 유지하려면 편집 범위가 한 화면 내에서 조작 가능해야 함

**현재 상태**:
- 현재 구현: 수동 웨이브 시작, 적 처치 골드, 생명 감소, 웨이브 간 build 전환이 존재
- 현재 한계: 다음 위협 정보와 결과 요약, 업그레이드/판매 입력, 웨이브 중 편집 UX 미확정
- 기획 방향: 웨이브 중 건설은 적극 장려하되, 모바일 오입력을 방지하는 범위에서 설계

### 20분 루프: 한 레벨

```text
맵 제약과 시작 자원 읽기
→ 초반 미로 골격 마련
→ 위협별 전문 타워 조합
→ 중반 자원 투자 방향 선택
→ 최종 보스/복합 웨이브 대비
→ 생존 또는 실패
→ 사용 전략과 개선 포인트 확인
```

- 현재 구현: 3개 레벨과 10웨이브 데이터가 있다.
- 20분은 **목표 가설**이며 현재 레벨의 실제 완료 시간은 검증되지 않았다.
- 승리는 현재 10웨이브와 모든 적 처리가 끝난 상태, 실패는 생명 0이다.

### 장기 반복 루프: 메타 진행을 통한 영구 성장 (승인됨)

**정의**: 플레이어가 레벨을 반복하면서 타워/업그레이드를 영구 해금하고 기지를 성장시킨다.

```text
레벨 완료 → 타워 또는 업그레이드 해금
→ 기지 메타 데이터 갱신
→ 다음 도전에서 새로운 타워/능력으로 진행
→ 같은 레벨을 다른 전략으로 재도전
→ 영구 성장의 느낌으로 반복 플레이 의욕 형성
```

**설계 세부사항**:
- **결과 화면**: "획득 타워", "업그레이드", "메타 진전" 중심 표시
  - 예: "불의 마법사 해금 (기존: 얼음 마법사)" 또는 "타워 사거리 +10% 영구 해금"
  - 단순 점수나 순위보다 "다음 판에 뭐가 달라지나"를 먼저 보여줌
- **저장 구조**: 플레이어 메타 상태(해금된 타워/업그레이드)를 영구 보관
  - 로컬 세이브 또는 클라우드 세이브 모두 가능
  - 각 레벨의 최고 성적(최소 자원 사용, 최대 생명 보존 등)을 선택 사항으로 추적 가능
- **향후 경제/메타 GDD**: 반복 플레이 의욕에 기반한 보상 곡선 설계
  - 너무 빠른 메타 해금은 선택 고갈로 이어짐
  - 너무 느린 해금은 반복 판단 의욕 저하
  - 초반 자주 해금, 후반 선택지 넓혀지기 패턴 고려

**타 모드와의 관계** (주의):
- 현재는 "라이트 플레이어"를 중심으로 기획하므로, 메타 해금이 초반 플레이를 복잡하게 하지 않는 범위에서만 진행
- 고급 모드(무제한 웨이브, 타임 어택 등)는 추후 고려 (이번 GDD 범위 외)

**포함하지 않는 것**:
- 시장 수익화 모델 (프리미엄 타워, 광고, 배틀패스 등) — 아직 비전 단계이므로 미결정
- 소셜 기능 (리더보드, 협력 플레이) — 싱글플레이어 경험 완성 후 고려

## 8. 차별화 방향 후보 3안

### 후보 A: 경로를 자원으로 만드는 미로 경제

- 한 줄 판타지: “벽 한 칸으로 적의 시간을 구매해 그 시간을 골드로 바꾼다.”
- 기존 타워 디펜스와 다른 점: 미로는 장식이나 완전 차단 수단이 아니라, 타워 사거리와 경제 효율을 바꾸는 투자 수단이다.
- 핵심 시스템 변화:
  - 경로 연장량과 실제 타워 노출 시간을 같은 정보로 보여준다.
  - 제안된 보상은 추가 이동 거리 자체가 아니라, 효율적 방어 선택이 만든 자원·생존 이점에 연결한다.
  - 벽 비용, 타워 위치, 특정 웨이브의 체류 시간을 함께 평가한다.
- 재미 임팩트: 5/5
- 구현 비용: 3/5
- 주요 위험:
  - 경로 시각화가 약하면 벽 투자의 결과를 이해하지 못함
  - 경로만 길게 만드는 단일 최적 배치가 등장할 수 있음
  - 보상 지표가 직접 수익화되면 반복 수익 exploit가 생길 수 있음
- 테스트 가능한 가설:
  - 같은 타워·골드에서 경로 노출 시간이 늘어난 배치가 더 높은 처치율을 보인다.
  - 플레이어가 벽 추가 후 경로 변화와 사거리 교차를 관찰하는 빈도가 증가한다.
  - 3종 이상 미로 형태가 서로 다른 웨이브에서 경쟁력 있게 승리한다.

### 후보 B: 위협 조합 퍼즐과 준비 방어

- 한 줄 판타지: “다음 적 부대를 읽고 한 웨이브에 맞는 방어 도형을 푼다.”
- 기존 타워 디펜스와 다른 점: 다음 웨이브를 숨기지 않고, 미리 보이는 정보로 최선의 조합을 고르는 퍼즐성을 강조한다.
- 핵심 시스템 변화:
  - 다음 웨이브 구성, 속성, 출현 순서의 명확한 정보
  - 타워별 역할과 대응 관계를 HUD에서 비교 가능하게 제공
  - 준비 시간에는 건설 비용이 정확히 표시되고, 웨이브 중 대규모 편집을 제한하는 선택안
- 재미 임팩트: 4/5
- 구현 비용: 2/5
- 주요 위험:
  - 정답 웨이브 조합 하나가 반복 최적화될 수 있음
  - 미리 알 수 있는 퍼즐이 미로 빌딩의 자유도를 낮출 수 있음
  - 반복적인 웨이브 UI 확인이 전술보다 메뉴 읽기에 편중될 수 있음
- 테스트 가능한 가설:
  - 위협 예고가 있을 때 플레이어의 첫 대응 선택 속도와 적중률이 올라간다.
  - 지상/공중, 빠름/느림, 체력/무리가 서로 다른 타워 조합을 유도한다.
  - 같은 미리보기에서 서로 다른 3종 이상의 유효한 대응 조합이 나온다.

### 후보 C: 웨이브 중 살아 있는 경로 전술

- 한 줄 판타지: “적이 가까워질 때 미로를 다시 접어 공격 기회를 되살린다.”
- 기존 타워 디펜스와 다른 점: 준비 후 관망하는 타워 디펜스가 아니라, 위기 시 경로를 수정해 적 흐름을 재편한다.
- 핵심 시스템 변화:
  - 이동 중인 적이 새 경로에 안전하고 결정적으로 합류
  - 제한된 실시간 편집 수량 또는 재배치 비용
  - 현재 적 위치와 변경 후 경로가 겹쳐 보여 오입력을 줄임
- 재미 임팩트: 4/5
- 구현 비용: 5/5
- 주요 위험:
  - 모바일에서 탭 정확도와 빠른 판단 부담이 커짐
  - 경로 변경이 적 이동을 비정상적으로 앞당기거나 역행시킬 수 있음
  - 자동으로 타이밍만 재는 단일 전략이 될 수 있음
- 테스트 가능한 가설:
  - 제한된 실시간 경로 편집이 있을 때 “아무 것도 하지 않는 관전 구간”이 줄어든다.
  - 플레이어가 위기 상황에서 경로 변경을 선택하지만, 전체 배치량의 과반을 준비 단계에서 결정한다.
  - 동일 시드 재현에서 경로 변경 결과가 동일하게 관찰된다.

## 9. 추천 방향

### 권장안

**후보 A: 경로를 자원으로 만드는 미로 경제**를 중심 방향으로 권장한다.
후보 B의 다음 위협 예고와 조합 다양성은 필수 보조 요소로 사용한다.
후보 C의 웨이브 중 편집은 현재 프로토타입에 있으므로 즉시 제거하지 않되,
UX·결정성·재미 검증 전에는 핵심 차별화나 필수 조작으로 승격하지 않는다.

### 선택 이유

1. 현재 구현의 BFS, 미로 빌딩, 경로 변경, 타워 역할 분리가 가장 직접적으로 검증할 수 있는 재미다.
2. 벽 배치, 경로 길이, 타워 노출 시간은 헤드리스 시뮬레이션으로 비교 가능한 가설을 만든다.
3. 먼저 경로 판단을 명확히 하면 모바일 탭 UX와 다음 기능의 우선순위를 함께 정할 수 있다.
4. 준비 전략과 실시간 편집을 모두 유지하되, 양쪽을 동시에 복잡하게 만들 필요가 없다.

### 거절한 대안과 이유

- 후보 C를 중심으로 삼는 안은 현재 이동 중 재경로화 안정성, 모바일 조작 정확도,
  오입력 비용이 검증되지 않아 초기 핵심으로 두기 어렵다.
- 단순 영구 수집·업그레이드 중심 타워 디펜스는 미로 설계 가치보다 외부 진행에
  플레이 동기가 집중되므로 이번 방향과 맞지 않는다.
- 영웅 직접 조작형 타워 디펜스는 한 손 입력과 관찰 가능성을 낮춰 후순위로 둔다.

### 보류한 결정

- 최종 출시 플랫폼 범위와 모바일 빌드 정책
- 장기 메타의 유무와 중심
- 미로 길이 자체 보상, 생존 효율 보상, 준비 시간 보상 중 경제 표현
- 업그레이드, 판매, 재배치의 공통 UX
- 웨이브 중 편집 허용량 또는 제한 방식

“미로 빌딩”을 핵심 재미의 중심으로 승인할지는 14절 질문 1의 결정 대상이다.

## 10. 전략 다양성 기준

### 의미 있는 선택 수

프로토타입 완료 판단에서는 다음 조건을 기준으로 한다.

- 핵심 선택이 최소 3종의 유효한 역할로 나뉜다: 경로 제어, 지속 화력, 위협 특화
- 동일 맵에서 최소 3개의 서로 다른 타워 조합 또는 미로 구조가 승리 가능하다.
- 한 웨이브에서 다음 질문 중 둘 이상이 실제 결과에 영향을 준다.
  - 어떤 칸에 건설하는가?
  - 무엇을 건설하는가?
  - 지금 건설하는가, 자원을 남기는가?
  - 어떤 타워를 강화하거나 교체하는가?

“많은 선택지”가 아니라, 선택에 따라 실제 승률 또는 자원 효율이 달라지는 수를 센다.

### 타워/적/경로/경제 상호작용

| 요소 | 다른 요소에 주는 영향 | 플레이어가 읽는 신호 |
|---|---|---|
| 경로 | 타워 노출 시간, 지상 적 진행, 벽 투자 효율 | 경로 길이·시간, 예상 위험 구간 |
| 타워 | 처치 속도, 감속, 대상 제한, 사거리 조합 | 사거리·역할·비용·효과 |
| 적 | 이동 속도, 체력, 지상/공중 대응 요구 | 다음 웨이브 구성과 진행 |
| 경제 | 새 배치, 강화, 재설계, 미래 준비 가능성 | 현재 골드, 예상 비용, 손익 피드백 |

경제가 경로와 역할 선택을 연결하지만 특정 탑재 방식만 누적 강화하는 시스템은 피한다.

### 단일 최적 전략을 피하는 기준

다음 중 하나라도 반복되면 밸런스 문제로 본다.

- 특정 타워 조합이 테스트 맵의 80% 이상에서 단독 최적이다.
- 미로 길이만 늘리면 골드·생명·승률이 동시에 항상 증가한다.
- 공중 또는 고체력 대응 없이 후반 웨이브를 안정적으로 통과한다.
- 벽을 사용하지 않는 전략과 벽을 최대한 사용하는 전략이 모두 의사결정 차이를 만들지 못한다.
- 동일 초기 자원을 가진 유효 전략 간 승률 차이가 크지만 위치·위협 요소가 아니라 코드 수치 하나에서만 발생한다.

수치는 후속 밸런스 문서에서 검증용 초기값으로 정한다. 이 문서에서는 전략 다양성의 판정 조건만 정한다.

## 11. 모바일 세로 UX 원칙

### 한 손 입력

- 모든 주요 조작은 엄지 한 번의 탭으로 선택, 배치, 확인까지 도달한다.
- 건설/웨이브/정보/전환 동작을 화면 하단부의 안정된 터치 영역에 둔다.
- 홀드는 보조 입력으로 쓰되 기본 행동의 필수 조건으로 두지 않는다.
- 웨이브 중 입력은 실수 시 비용과 되돌리기 조건을 보여준다.

### 탭 정확도

- 셀 크기는 손가락 직경보다 충분히 크거나, 현재 선택 셀을 명확히 확대 표시한다.
- 손가락 아래를 가리는 요소를 피하고 탭 시 미리보기 → 확정의 기회를 제공한다.
- 배치가 불가능한 이유(금지 위치, 경로 차단, 비용 부족)를 셀 또는 짧은 HUD 메시지로 알려준다.
- 경계·HUD·맵 사이 탭 소유권은 한 번에 하나의 결과만 발생해야 한다.

### HUD 가독성

- 상시 정보는 골드, 생명, 웨이브, 현재 건설 선택으로 제한한다.
- 다음 위협과 상세 타워 정보는 필요할 때 확장하되, 맵을 장시간 가리지 않는다.
- 색만으로 역할을 구분하지 않고 아이콘/형태/짧은 라벨을 병행한다.
- 사거리, 경로, 적 진행, 자원 변화를 한 화면에서 비교할 수 있어야 한다.

### 맵과 정보 영역의 우선순위

1. 입구·출구·현재 경로·위험 구간
2. 배치 후보와 타워 사거리
3. 선택 가능한 건설 도구
4. 골드·생명·웨이브 요약
5. 장식 및 상세 통계

현재 14×9, 60px 셀 맵과 180px 하단 HUD는 화면 구조를 보여주는 구현 사실일 뿐,
세로 화면에서 모든 경로와 터치 영역이 동시에 보이는 최종 배치 기준은 아직 아니다.
스크롤/줌/표시 축소 중 무엇을 선택할지는 플레이 가능성과 정확도 테스트 뒤 결정한다.

## 12. 재미 성공 기준

### 플레이 관찰로 확인 가능한 행동

| 기준 | 관찰 가능한 신호 | 성공 예시/판정 원칙 |
|---|---|---|
| 경로 설계 이해 | 벽 배치 후 플레이어가 경로 변화를 직접 보고 설명함 | 설명이 연출이나 HUD 문구가 아니라 실제 경로 변화를 가리킴 |
| 의미 있는 배치 | 같은 칸에 타워만 놓지 않고 벽·타워·저축 중 선택함 | 관찰 세션에서 세 행동이 모두 목적에 따라 나타남 |
| 조합 이해 | 서로 다른 적에 다른 역할 타워를 사용함 | “공중용”, “감속”, “고체력 대응”을 행동으로 구분 |
| 실패 원인 학습 | 실패 후 특정 위치·타워·자원 결정을 수정함 | 다음 판에서 같은 실수를 줄이고 다른 전략을 시도 |
| 입력 신뢰 | 의도한 셀과 실제 배치 결과가 일치함 | 오배치/재시도 횟수가 낮고 거부 이유를 이해 |

### 헤드리스 시뮬레이션으로 확인 가능한 지표

현재 하네스는 경로 탐색, 맵 배치, 타워, 적, 웨이브, 경제의 단위 동작을 검증한다.
방향 검증에는 아래 통합·시뮬레이션 지표가 추가로 필요하다.

- 동일한 맵·웨이브·배치에서 최종 생명/골드/처치율이 결정적으로 재현됨
- 유효 배치 전략별 성공률, 생존 생명, 평균 적 체류 시간, 노출 타격량
- 타워 타입별 선택·공격·처치 기여도와 유휴 시간
- 벽 투자 대비 추가 경로 길이 및 그로 인한 총 노출 사격 시간
- 지상/공중, 빠른/느린, 고체력 적에 대한 누수율
- 단일 전략 과다 승률과 서로 다른 전략의 파레토 비교
- 이동 중 경로 재배치가 역행, 순간 이동, 출구 우회 같은 비정상 이동을 만들지 않음

수치 임계값은 밸런스 문서에서 고정한다. 이 문서에서는 “측정 가능”과
“서로 다른 유효 전략의 존재”를 재미 판정의 최소 조건으로 둔다.

### 최종 플레이 검증 항목

- 첫 진입에서 1분 안에 벽과 타워 배치의 차이를 실행하고 설명할 수 있는가?
- 한 판 동안 플레이어가 최소 세 가지 전략적 질문을 스스로 던지는가?
- 실패가 입력 오류 때문인지 전략 오류 때문인지 구분 가능한가?
- 지상·공중·고속·고체력 대응이 서로 다른 의사결정을 요구하는가?
- 세로 화면에서 모든 기본 행동을 한 손 탭으로 완료할 수 있는가?
- HUD가 가리거나 착각시킨 셀이 반복해서 생기지 않는가?
- 두 번째 판에서 첫 판의 관찰을 반영한 배치 변화가 나타나는가?

최종 플레이 검증은 헤드리스 지표가 통과한 뒤 최소 실행으로 수행한다.
입력, 렌더링, 탭 정확도처럼 코드 하네스로 재현되지 않는 항목만 런타임에서 확인한다.

## 13. 현재 구현 대비 갭

### 이미 구현된 것

| 범위 | 현재 구현 사실 | 상태 주석 |
|---|---|---|
| 플랫폼/프레임 | 세로 창, 가상 해상도, 고정 타임스텝, 씬 스택 | 기술 기반, 게임 방향 결정은 아님 |
| 입력 | 터치/마우스 탭 통합, 홀드 스냅샷 | 실기기 UX는 미검증 |
| 맵/경로 | 오픈 그리드, 벽/타워 배치, BFS, 완전 차단 방지 | 미로 빌딩의 기술적 기초 |
| 전투 | Gun/Slow/Rocket/Anti-Air, 사거리·공격·감속 | 업그레이드/판매 UI는 없음 |
| 적 | Normal/Fast/Tank/Flyer/Boss, 지상/공중 이동 | 역할 다양성 존재, 밸런스 검증 부족 |
| 콘텐츠 | 3개 레벨, 10웨이브 | 레벨별 학습 목적과 난이도 곡선 미정 |
| 경제 | 골드, 구매, 처치 보상, 생명과 게임오버 | 보상 구조의 재미·경로 효율 연결 부족 |
| UI | 하단 건설 선택, 정보, 웨이브 시작 버튼 | 모바일 가시성과 탭 정확도 미검증 |
| 테스트 | 6개 헤드리스 단위 하네스 | 통합 승률·전략 다양성·UX 테스트 없음 |

### 제안된 기능

- 배치 전후 경로 길이와 타워 노출 시간 미리보기
- 다음 웨이브 위협 정보와 대응 역할 표시
- 선택 타워의 업그레이드/판매/재배치 인터페이스
- 웨이브·레벨 결과의 원인 요약
- 경로 변경 시 이동 중 적의 안전한 합류 규칙
- 전략 평가를 위한 결정적 통합 시뮬레이션
- 미로 효율과 타워 조합이 상호작용하는 보상 또는 경제 피드백

위 항목은 모두 제안이며, 후속 GDD와 UX/밸런스 문서에서 우선순위와 범위를 승인해야 한다.

### 구조적 위험

1. 현재 맵은 14행×60px로 840px이고 하단 HUD는 180px이다. `mapOffsetY`는
   현재 사용되지 않아 세로 화면에서 모든 셀·HUD가 동시에 안전하게 보이는지
   보장할 수 없다.
2. 이동 중 적의 경로 재설정은 새 경로에서 가장 가까운 웨이포인트를 선택한다.
   실시간 변경의 역행·우회·순간 이동 가능성을 통합 시뮬레이션으로 검증해야 한다.
3. 타워 강화와 판매 계산은 모듈에 있으나 게임 플레이 입력과 경제 흐름에 연결되지 않았다.
   수치 존재가 기획된 기능을 의미하지 않는다.
4. 10웨이브 데이터는 다양하지만 레벨별 교육 단계, 전략 변화, 승률 측정이 문서화되지 않았다.

### 아직 기획되지 않은 부분

- 타워와 적의 최종 역할 간 상성
- 벽의 경제적 목적과 적정 비용 원칙
- 배치·업그레이드·판매·재배치의 공통 UX
- 레벨별 학습 목표, 난이도 곡선, 콘텐츠 생성 규칙
- 실패/승리 보상과 장기 반복의 목적
- 정지/일시정지, 속도 변경, 중간 저장의 필요성
- 접근성, 사운드, 아트 톤, 최종 출시 범위

장기 반복과 수익화 관련 범위는 시장·운영 결정이 승인되기 전 기획의 전제로 삼지 않는다.

## 14. 기획 결정 질문

최대 5개로 제한한다. 각 답은 아래 문서나 구현의 다음 결정을 푼다.

1. **✓ 미로 빌딩 승인**: 미로 빌딩을 핵심 재미의 중심으로 승인하는가?
   - **결정**: 예, 승인
   - 미로 빌딩(경로 편집)을 게임의 핵심 재미로 확정한다.
   - 적용: GDD 핵심 규칙, 코어 루프, 첫 마일스톤이 미로 메커닉 중심으로 설계됨
   - 근거: 현재 BFS·맵·타워 역할 프로토타입이 직접 검증 가능

2. **✓ 목표 플레이어**: 라이트 플레이어와 타워 디펜스 숙련자 중 누구를 우선 설명·난이도 기준으로 삼는가?
   - **결정**: 라이트 플레이어 중심
   - 타워 디펜스 미경험 플레이어가 경로와 배치의 직관적 결과로 학습하도록 설계
   - 적용: GDD 튜토리얼은 "벽 → 타워 → 조합" 순으로 한 개념씩 소개
   - 적용: 레벨 난이도는 초반에는 단순 위협, 중반 이후 혼합 위협으로 진행
   - 적용: UX 정보는 필수 의사결정 항목만 강조, 세부 수치는 옵션 정보로 처리

3. **✓ 한 판 시간**: 목표 한 판 시간을 10분, 20분, 30분 이상 중 어디에 둘 것인가?
   - **결정**: 약 20분 (표준 세션)
   - 한 번의 집중 판단 30초, 웨이브 단위 약 3분 기준을 유지
   - 적용: 목표 웨이브 수 약 6~8개, 레벨 콘텐츠 분량 설정
   - 적용: 세션 검증은 평균 플레이 타임 측정으로 확인

4. **✓ 장기 반복 동기**: 레벨 진행, 기록 도전, 영구 성장 중 무엇을 중심으로 할 것인가?
   - **결정**: 영구 성장 (해금, 메타 발전)
   - 플레이어는 레벨을 반복하면서 타워/업그레이드를 영구 해금하고 기지를 성장시킨다
   - 적용: 결과 화면은 "획득 타워", "업그레이드", "메타 진전" 중심으로 설계
   - 적용: 저장 구조는 플레이어 기지 상태, 타워 해금, 업그레이드 기록을 보관
   - 적용: 향후 경제/메타 GDD는 반복 플레이 의욕에 기반한 보상 곡선 설계
   - 주의: 시장·수익화 결정은 아직 요구하지 않음

5. **✓ 실시간 편집 위치**: 웨이브 중 경로 편집을 핵심 조작, 제한적 보조, 웨이브 사이에만 가능한 기능 중 어디로 둘 것인가?
   - **결정**: 핵심 조작 (웨이브 중 적극적으로 사용)
   - 웨이브 중 경로를 즉시 편집하고 그 결과를 바로 본다는 행동 자체가 핵심 의사결정
   - 적용: 이동 중 경로 갱신 규칙은 경로 변경 순간의 명확한 반응(적의 재경로지정)으로 설계
   - 적용: 모바일 입력 UX는 오입력 위험을 고려한 "확인 타월" 또는 취소 메커니즘 추가
   - 적용: 관련 하네스는 경로 변경의 즉각적 효과 검증에 초점

질문은 이 절에서 ✓ 표시를 붙인 5개이며, 모두 사용자 답변을 반영했다.

## 15. 다음 문서

### 1) GDD

- 이 비전의 플레이 경험을 입력, 규칙, 상태 변화, 성공/실패 조건으로 구체화한다.
- 후보 A를 중심으로 플레이어 의사결정, 제외 항목, 검증 가설을 정리한다.
- 수치와 콘텐츠는 예시/가설/확정 상태를 명확히 분리한다.

### 2) 밸런스 문서

- 벽, 타워, 적, 골드, 생명의 초기 수치와 변화 구간을 정의한다.
- 단일 최적 전략 방지, 경로 효율, 타워 기여도, 웨이브 난이도를 정량화한다.
- 모든 임계값은 결정적 시뮬레이션에서 먼저 검증한다.

### 3) 레벨/콘텐츠 문서

- 각 레벨의 학습 목표, 공간 제약, 위협 순서, 의도된 전략 변화를 정의한다.
- 동일 스킨 교체가 아니라 플레이어 질문이 다른 콘텐츠인지 검토한다.

### 4) UX 문서

- 한 손 입력, 배치 미리보기, 탭 정확도, HUD 우선순위, 경로/사거리 피드백을 정의한다.
- 현재 맵 크기와 하단 HUD가 세로 화면에 함께 안전하게 들어오는 방식을 검증 기준으로 잡는다.

### 5) 마일스톤 로드맵

- 문서 승인 → 헤드리스 통합 검증 → 최소 플레이 검증 → 기능 마일스톤 순서로 나눈다.
- 각 마일스톤은 구현 파일 목록보다 플레이어 행동과 종료 조건을 우선 기술한다.

### 우선 작성 순서

1. **GDD**: 추천 방향과 확인 질문을 합의 가능한 규칙으로 전환
2. **UX 문서**: 미로 판단과 세로 모바일 배치 정확도의 검증 방식 선행
3. **밸런스 문서**: 역할 상성, 경제, 통합 시뮬레이션 지표 고정
4. **레벨/콘텐츠 문서**: GDD와 밸런스 기준을 3개 레벨의 학습 목적에 적용
5. **마일스톤 로드맵**: 승인된 문서만 검증 가능한 구현 단계로 분할

## 승인 기준

- [ ] 핵심 방향 질문 5개가 결정되었다.
- [ ] 추천 방향이 GDD의 플레이어 행동으로 변환된다.
- [ ] 후보 A/B/C 중 채택·보조·보류 관계가 승인된다.
- [ ] 현재 구현 사실과 미구현 제안이 계속 구분된다.
- [ ] 재미 성공 기준에 관찰 지표 또는 헤드리스 지표가 연결된다.
- [ ] 기술 패턴, 수익화, 아트 방향을 이 비전에서 추측 없이 보류했다.

승인 후 상태를 `Approved`로 바꾸고, 변경 이력과 승인 날짜를 이 문서에 추가한다.
