# AI 바이브 코딩 토론 가이드

## 토론 목표
- AI 협업 개발 경험을 객관적으로 돌아본다
- 바이브 코딩의 가능성과 한계를 구체적 사례로 탐색한다
- 졸업 후 AI와 함께 일하는 **자기 방식**을 설계하게 한다

> 이 토론은 수업 회고가 아니라, 학생들이 사회에 나가서 AI와 함께 일하는 방식을 미리 설계하는 시간입니다. 취업이든 인디 개발이든, "도구를 잘 쓰는 개발자"의 기준을 스스로 세우도록 유도해 주세요.

---

## 사전 준비 (토론 전 5분)

아래 중 1개 이상을 떠올려 메모해 오세요.

1. AI에게 지시했을 때 **가장 기대 이상**이었던 순간
2. AI가 **가장 엉뚱한 결과**를 냈던 순간
3. AI 없이 혼자 했으면 **더 빨랐을 것 같은** 작업
4. AI 덕분에 **처음 알게 된** 개념이나 패턴

## 토론 주제 (3개 중 택 1~2)

### 주제 A: "AI가 짠 코드는 내 코드인가?"

| 질문 | 생각해볼 점 |
|------|-------------|
| 내가 프롬프트를 쓰고, 검증하고, 수정했으면 "내 코드"인가? | 설계 의도 vs 타이핑 노동 |
| 코드를 한 줄도 안 건드렸는데 잘 돌아간다면? | 이해 없는 사용의 위험 |
| 팀원이 AI로 만든 코드를 PR 올렸는데 설명을 못 한다면? | 코드 리뷰의 의미 변화 |
| 면접에서 "이 코드 설명해보세요"라고 하면? | 소유 = 설명 가능성? |

**토론 포맷**: 스펙트럼 투표 → "100% 내 코드다" ~ "내 코드가 아니다" 사이 자기 위치 선택 → 양 극단 대표가 논거 발표

---

### 주제 B: "바이브 코딩의 천장은 어디인가?"

| 질문 | 생각해볼 점 |
|------|-------------|
| AI가 아키텍처를 잡아줬을 때, 그 구조가 최선이었나? | 초기 설계의 질 |
| 버그를 고치라고 했더니 다른 버그가 생긴 경험은? | 컨텍스트 한계 |
| "게임이 재미있게" 같은 모호한 지시는 통하던가? | 감각적 판단의 영역 |
| 프로젝트 규모가 커지면 AI 효율이 올라가나, 내려가나? | 스케일과 복잡도 |
| 테스트 하네스를 AI가 만들었을 때, 빠진 케이스가 있었나? | 검증의 검증 문제 |

**토론 포맷**: 소그룹(3~4명) 경험 공유 → 각 그룹이 "AI가 잘하는 것 TOP 3 / 못하는 것 TOP 3" 발표

---

### 주제 C: "졸업 후 나는 AI를 어떻게 쓸 것인가?"

| 질문 | 생각해볼 점 |
|------|-------------|
| 취업 면접에서 "AI와 함께 만들었다"고 말할 건가, 숨길 건가? | 투명성 vs 현실 |
| 인디 개발자로 1인 출시를 한다면, AI 없이도 유지보수할 수 있는가? | 자립 가능성 |
| 회사에서 AI 사용을 금지하면 나의 생산성은 어떻게 되는가? | 도구 의존도 |
| AI가 6개월마다 바뀌는데, 지금 익힌 전략은 이전 가능한가? | 이전 가능한 역량 |
| AI가 못하는 영역에서 내가 투자할 공부는 무엇인가? | 차별화 전략 |

**토론 포맷**: 취업 경로 vs 인디 경로로 나눠 각자 "AI 활용 전략 3줄"을 작성 → 교차 공유

## 진행 타임라인 (50분 기준)

| 시간 | 단계 | 활동 |
|------|------|------|
| 0~5분 | 워밍업 | 사전 준비 메모 1개를 짝과 공유 |
| 5~10분 | 주제 선택 | 교수자가 주제 소개, 학생 입장 선택 (거수/이동/투표) |
| 10~25분 | 소그룹 토론 | 같은 입장 3~4명이 논거 + 구체 사례 정리 |
| 25~40분 | 교차 토론 | 반대 입장과 질문-응답 (팀 대 팀 또는 1:1) |
| 40~47분 | 전체 공유 | 각 그룹 핵심 논점 1문장 발표 |
| 47~50분 | 마무리 | 교수자 요약 + 열린 질문 제시 |

## 교수자용 퍼실리테이션 팁

### 분위기 조성
- "정답 없음"을 명시적으로 선언하고 시작
- 경험 기반 발언을 유도: "너는 실제로 어땠어?"
- 침묵이 길면 구체적 상황 제시: "pathfinder.lua를 AI가 만들었을 때 BFS 로직을 바로 이해했나?"

### 깊이 유도 질문 (막힐 때 사용)
- "그 판단은 AI가 했나, 너가 했나?"
- "그걸 검증하려면 뭘 알아야 하나?"
- "만약 AI가 없었다면 그 시간에 뭘 했을까?"
- "worklog를 보면 어디서 가장 오래 걸렸나?"

### 마무리 — 행동으로 이어지는 질문
- "졸업 후 첫 3개월 동안 AI를 활용해 만들 첫 번째 것은?"
- "이 수업에서 얻은 AI 협업 습관 중 계속 쓸 1가지는?"
- "AI가 못하는 영역에서 내가 투자할 공부 1가지는?"

## 토론 후 연결 활동 (선택)

1. **회고 작성**: 토론에서 인상 깊었던 논점 1개를 과제 보고서 회고 섹션에 반영
2. **worklog 재검토**: 자신의 작업 로그에서 "AI 의존도가 높았던 구간"과 "내가 주도한 구간"을 구분 표시
3. **프롬프트 리뷰**: 가장 효과적이었던 프롬프트 3개를 뽑아 "왜 잘 됐는지" 분석
