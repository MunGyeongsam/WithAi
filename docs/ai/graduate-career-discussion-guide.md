# 학교를 마친 후 단련 전략 토론 가이드 (교수자용)

> 기반 문서: [graduate-career-guide-ai-era.md](./graduate-career-guide-ai-era.md)
> 학생 배포용: [graduate-career-discussion-student.md](./graduate-career-discussion-student.md)
> 이전 토론: [vibe-coding-discussion-guide.md](./vibe-coding-discussion-guide.md) (AI 협업 경험 회고 중심)

## 토론 목표
- 좁은 신입 채용 시장을 **있는 그대로** 받아들이되, 불안이 아닌 **계획**으로 바꾼다
- "무엇을 단련할 것인가"를 **각자의 목표 직군** 기준으로 스스로 정하게 한다
- 토론이 끝나면 각자 **학교를 마친 후 3개월 단련 계획 1장**을 손에 쥐고 나가게 한다

> 이전 토론이 "AI와 어떻게 일할 것인가"였다면, 이번 토론은 **"문이 열릴 때까지 무엇을 단련할 것인가"**입니다. 정답을 주기보다, 학생이 자기 선택에 **근거**를 붙이도록 유도해 주세요.

> ⚠️ **참여 학생 구성:** 이번 학기를 끝으로 졸업하는 **3학년**과, 학교 사정으로 이번 학기를 끝으로 이 학교에서의 학업을 마치는 **2학년**이 함께합니다. 2학년은 학적 처리가 아직 확정되지 않았을 수 있습니다. 아래 "2학년이 함께하는 토론 운영"을 먼저 읽어 주세요.

---

## 사전 준비 (토론 전 과제)

학생에게 미리 배포한 뒤 아래를 메모해 오게 합니다.

1. 기반 문서를 읽고 **가장 공감한 부분 1개, 가장 동의하지 않는 부분 1개**
2. 지금 생각하는 **목표 직군** (Unity 클라이언트 / 엔진·그래픽스 / 툴·시스템 / 게임 서버 / 게임 밖 인접 분야 / 미정)
3. 이 학교에서 만든 것 중 **면접에서 가장 자신 있게 설명할 수 있는 결과물 1개**와, **설명이 막히는 부분 1개**

## 토론 주제 (5개 중 택 2~3)

### 주제 1: "좁은 문 앞에서 — 기다릴 것인가, 돌아갈 것인가?"

| 질문 | 생각해볼 점 |
|------|-------------|
| 원하는 회사에 붙을 때까지 준비만 할 것인가, 인접 직군·작은 회사부터 시작할 것인가? | 첫 경력의 가치 vs 방향 이탈 위험 |
| 준비 기간이 1년을 넘어가면 무엇이 가장 무너질까? (실력/돈/멘탈/관계) | 지속 가능성 |
| "공백기"를 "독립 개발 기간"으로 만들려면 무엇이 남아야 하나? | 증거로서의 기록 |
| 인디 출시, 게임잼, 오픈소스 기여는 경력으로 인정받을까? | 경력의 정의 |
| (2학년) 국비지원 교육, 바로 취업·인턴, 인디 개발 중 무엇을, 어떻게 조합할까? | 남은 1년을 대신할 커리큘럼과 공동체 |

**토론 포맷**: 스펙트럼 투표 → 교실 한쪽 끝 "목표 회사만 노린다", 반대쪽 끝 "일단 어디든 시작한다" 사이에 서기 → 양 끝과 가운데 대표가 각자의 조건(경제 상황, 목표)과 함께 논거 발표

### 주제 2: "AI 시대에도 수학과 글쓰기인가?"

| 질문 | 생각해볼 점 |
|------|-------------|
| 프로젝트 중 수학을 몰라서 AI 결과를 의심하지 못한 경험이 있나? | 판단의 근거 |
| 게임 수학 공식을 AI가 줬을 때, 맞는지 어떻게 확인했나? | 검증 방법 |
| README, 작업 로그, 프롬프트를 쓰면서 생각이 정리된 경험은? | 생각의 도구로서의 글 |
| "문장은 AI가 다듬는다"면 사람이 할 글쓰기는 무엇인가? | 구조화 vs 문장력 |
| 수학과 글쓰기에 주 몇 시간을 투자할 것인가? | 현실적 배분 |

**토론 포맷**: 찬반 토론 — 논제 "AI 시대 신입 개발자에게 수학·글쓰기는 코딩 실력보다 우선이다" → 찬성·반대 각 3분 입론 → 2분 반론 → 청중 질문 → 마지막에 **입장 변경 여부** 손들기

---

### 주제 3: "Unity만으로 충분한가, 저수준까지 내려가야 하나?"

| 질문 | 생각해볼 점 |
|------|-------------|
| Unity 프로젝트에서 성능 문제를 "원리로" 설명할 수 있었나? | 드로우콜, GC, 캐시 |
| LÖVE2D에서 직접 만든 게임 루프·충돌 경험이 Unity 이해에 도움이 됐나? | 엔진 없는 개발의 가치 |
| OpenGL/DirectX 미니 렌더러를 만드는 데 2개월을 쓴다면, 그만한 가치가 있나? | 기회비용 |
| Win32 API는 아직 배울 가치가 있나, OS 개념만으로 충분한가? | API vs 원리 |
| AI가 보일러플레이트를 다 짜 준다면, 저수준 학습의 의미는 무엇인가? | 디버깅 능력 |

**토론 포맷**: 직군별 그룹 — 목표 직군이 같은 학생끼리 3~4명 그룹 → 기반 문서 10장의 **직군별 추천표를 우리 그룹 기준으로 다시 작성** → 원래 표와 무엇이 다른지 발표

---

### 주제 4: "내 포트폴리오, 면접관은 무엇을 볼까?"

| 질문 | 생각해볼 점 |
|------|-------------|
| 팀 프로젝트에서 "내가 맡은 부분"을 1분 안에 설명할 수 있나? | 기여의 명확성 |
| AI로 만든 바이브 코딩 프로젝트를 포트폴리오에 넣을 것인가? 어떻게 설명할 것인가? | 투명성 + 판단력 증명 |
| "AI가 틀렸던 사례와 내가 잡아낸 과정"을 말할 수 있나? | 검증 능력의 증거 |
| 완성작 1개 vs 미완성 여러 개, 어느 쪽이 나을까? | 완주 능력 |
| 성능 개선 수치(전·후)를 보여줄 수 있는 프로젝트가 있나? | 측정 습관 |

**토론 포맷**: 모의 면접 롤플레이 — 2인 1조로 면접관·지원자 역할 → 기반 문서 7장 질문 중 2개로 3분씩 → 역할 교대 → 면접관 역할에서 **"이 답변에서 믿음이 간 부분 / 의심이 간 부분"** 피드백

---

### 주제 5: "개발자가 아닌 사람들에게 AI 시대는?" (확장 주제)

| 질문 | 생각해볼 점 |
|------|-------------|
| 부모님이나 친구가 AI 때문에 겪은 일(편리함, 사기, 불안)이 있나? | 일반인의 체감 |
| 개발자인 내가 주변 사람에게 알려줄 수 있는 것은? | 전문가의 사회적 역할 |
| 일반인과 개발자가 공통으로 단련해야 할 것은 무엇인가? | 정보 검증 = 코드 검증 |
| 내가 만드는 게임이 AI 시대의 사용자에게 어떤 가치를 줄 수 있을까? | 사람 중심 관점 |

**토론 포맷**: 자유 토론 또는 짧은 발표 — 기반 문서 부록을 읽고 **"가족에게 꼭 전하고 싶은 한 가지"**를 한 문장으로 쓰고 공유

## 교수자용 퍼실리테이션 팁

### 2학년이 함께하는 토론 운영
- 시작할 때 2학년의 상황을 **짧고 담담하게** 언급해 주세요. "여러분의 선택이 아니었다는 것을 알고 있다"는 한마디가 큰 힘이 됩니다. 다만 학교 결정에 대한 논쟁으로 번지지 않게 합니다.
- 학적 처리처럼 **확정되지 않은 사실은 추측으로 답하지 마세요.** "확인되는 대로 알려 주겠다" 또는 "학사 담당 부서에 이렇게 확인하라"로 안내합니다 (기반 문서 12장 체크리스트).
- 그룹을 짤 때 **2학년과 3학년을 섞는** 것을 권합니다. 3학년은 곧 사회에 나가는 가장 가까운 선배이고, 2학년의 질문은 3학년에게도 자기 점검이 됩니다.
- 주제 1에서 2학년은 **국비지원 교육 / 바로 취업·인턴 / 인디 개발** 세 선택지를 축으로 이야기하게 하면 구체적인 논의가 됩니다.
- 마무리 계획서에서 2학년은 **"학기 종료 전 확인할 것"** 칸을 반드시 채우게 해 주세요.
- 가능하면 3학년 과정의 **과목 목록과 핵심 내용**을 2학년에게 나눠 주세요. 독학 계획의 뼈대가 됩니다.

### 분위기 조성
- 취업 이야기는 **불안을 자극하기 쉽습니다.** 시작할 때 "오늘은 걱정을 나누는 자리가 아니라 계획을 세우는 자리"라고 분명히 말해 주세요.
- 개인의 경제 사정이나 진로 고민은 **원하는 만큼만** 공유하게 합니다. 발표를 강요하지 마세요.
- "정답은 없다, 단 근거는 있어야 한다"를 기본 규칙으로 둡니다.

### 깊이 유도 질문 (막힐 때 사용)
- "그 선택을 하면 **6개월 뒤** 무엇이 남아 있을까요?"
- "그걸 면접에서 어떻게 **증명**할 수 있을까요?"
- "AI가 그 일을 대신해 준다면, **여러분에게 남는 일**은 무엇인가요?"
- "반대 입장이 가장 강하게 주장할 수 있는 논거는 무엇일까요?"
- "이 학교에서 한 것 중 **그 주장을 뒷받침하는 경험**이 있나요?"

### 흔한 흐름과 대응
| 흐름 | 대응 |
|------|------|
| "어차피 AI가 다 할 텐데요" (냉소) | "그럼 AI 결과가 틀렸을 때 누가 알아채나요?"로 검증 논의로 전환 |
| "저수준은 다 필요 없어요" (극단) | 직군별 추천표를 보여주며 "어떤 직군이라면 필요할까?"로 조건화 |
| 막연한 불안만 반복 | "그 불안을 **이번 주에 할 수 있는 행동 1개**로 바꾼다면?" |
| 학교 결정에 대한 분노·허탈감 (2학년) | 감정을 인정한 뒤 "확인할 사실"과 "내가 고를 수 있는 다음 걸음"으로 나눠 정리 |
| 특정 학생만 발언 | 포스트잇 익명 의견 → 교수자가 읽어 주기 |

### 마무리 — 행동으로 이어지는 질문
- "학교를 마친 후 **첫 주 월요일 오전**에 무엇을 하고 있을 건가요?"
- "3개월 뒤의 나에게 어떤 **결과물 1개**를 약속하겠습니까?"
- "막혔을 때 **연락할 사람** 한 명은 누구입니까?"

## 토론 후 연결 활동 (선택)
- **3개월 단련 계획서** 제출 (학생용 문서의 양식 사용). 원하는 학생에 한해 3개월 뒤 교수자에게 진행 상황 메일 보내기
- **동기 스터디 결성:** 목표 직군이 같은 학생끼리 학교를 떠난 후에도 주 1회 온라인 회고 (2학년과 3학년을 섞으면 더 좋습니다)
- **포트폴리오 상호 리뷰:** 2주 안에 서로의 README를 읽고 "설명이 막히는 곳" 표시해 주기
- **기술 글 1편 쓰기:** 오늘 토론에서 바뀐 생각을 주제로 블로그 글 작성
