# AI 바이브 코딩 토론 — 학생용 가이드

## 토론 목표
- AI 협업 개발 경험을 솔직하게 돌아본다
- 바이브 코딩의 가능성과 한계를 구체적 사례로 탐색한다
- 졸업 후 AI와 함께 일하는 **나만의 방식**을 설계한다

---

## 사전 준비 (토론 시작 전에 메모해 오세요)

아래 중 **1개 이상** 떠올려 짧게 적어 오세요.

1. AI에게 지시했을 때 **가장 기대 이상**이었던 순간
2. AI가 **가장 엉뚱한 결과**를 냈던 순간
3. AI 없이 혼자 했으면 **더 빨랐을 것 같은** 작업
4. AI 덕분에 **처음 알게 된** 개념이나 패턴

> 💡 worklog나 커밋 이력을 훑어보면 떠올리기 쉽습니다.

---

## 토론 주제

### 주제 A: "AI가 짠 코드는 내 코드인가?"

- 내가 프롬프트를 쓰고, 검증하고, 수정했으면 "내 코드"인가?
- 코드를 한 줄도 안 건드렸는데 잘 돌아간다면?
- 팀원이 AI로 만든 코드를 PR 올렸는데 설명을 못 한다면?
- 면접에서 "이 코드 설명해보세요"라고 하면?

**생각의 축**: 설계 의도 vs 타이핑 노동 / 이해 vs 사용 / 소유 = 설명 가능성?

---

### 주제 B: "바이브 코딩의 천장은 어디인가?"

- AI가 아키텍처를 잡아줬을 때, 그 구조가 최선이었나?
- 버그를 고치라고 했더니 다른 버그가 생긴 경험은?
- "게임이 재미있게" 같은 모호한 지시는 통하던가?
- 프로젝트 규모가 커지면 AI 효율이 올라가나, 내려가나?
- 테스트를 AI가 만들었을 때, 빠진 케이스가 있었나?

**생각의 축**: 컨텍스트 한계 / 감각적 판단의 영역 / 검증의 검증 문제

---

### 주제 C: "졸업 후 나는 AI를 어떻게 쓸 것인가?"

- 취업 면접에서 포트폴리오 코드를 "AI와 함께 만들었다"고 말할 건가, 숨길 건가?
- 인디 개발자로 1인 출시를 한다면, AI 없이도 유지보수할 수 있는가?
- 회사에서 AI 사용을 금지하면 나의 생산성은 어떻게 되는가?
- AI가 6개월마다 바뀌는데, 지금 익힌 프롬프트 전략은 이전 가능한가?
- AI가 못하는 영역에서 내가 투자할 공부는 무엇인가?

**생각의 축**: 취업 vs 인디 경로 / 도구 의존도 자가 진단 / 이전 가능한 역량

## 진행 순서 (50분)

| 시간 | 활동 |
|------|------|
| 5분 | 사전 메모를 짝과 공유 (워밍업) |
| 5분 | 주제 소개 → 입장 선택 |
| 15분 | 같은 입장 소그룹(3~4명)에서 논거 + 사례 정리 |
| 15분 | 반대 입장과 교차 토론 (질문-응답) |
| 7분 | 전체 공유 — 각 그룹 핵심 1문장 발표 |
| 3분 | 마무리 |

---

## 토론 규칙

1. **경험으로 말하기** — "~라고 생각한다" 대신 "내 프로젝트에서 ~했을 때"
2. **정답 없음** — 찬반 어느 쪽이든 구체적 근거가 있으면 OK
3. **질문 환영** — 상대 의견에 "왜?"라고 묻는 것이 공격이 아님
4. **사례 구체적으로** — 파일명, 상황, 결과까지 말할수록 좋음

---

## 토론 후 활동 (선택)

- 토론에서 인상 깊었던 논점 1개를 과제 보고서 **회고 섹션**에 반영
- worklog에서 "AI 의존도가 높았던 구간"과 "내가 주도한 구간"을 구분 표시
- 가장 효과적이었던 프롬프트 3개를 뽑아 "왜 잘 됐는지" 분석

## 마무리 — 내일부터의 1가지

- 졸업 후 첫 3개월 동안 AI를 활용해 만들 **첫 번째 것**은?
- 이 수업에서 얻은 AI 협업 습관 중 **계속 쓸 1가지**는?
- AI가 못하는 영역에서 **내가 투자할 공부 1가지**는?
